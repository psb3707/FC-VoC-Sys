# 12. 일정·마일스톤·위험·개발 순서

## 1. 개발 순서 (강제)
`DOCS` → `FRONTEND`(기능 없는 화면) → `BACKEND`(구현·연결) → `RELEASE`(12/4~). 순서는 `docs/gates/PHASE` 와 `check_phase.py` 가 강제하고, 단계 전환은 승인 없이 일반 PR로 한다(ADR-010). 마일스톤 M1~M3 는 일정 지표다.

| 단계 | 할 수 있는 일 | 막는 일 | 다음 단계 진입 조건 |
|---|---|---|---|
| DOCS | `docs/`, 규칙·훅 파일, `assets/`, Git 제외 `spikes/` | `src/`, `pom.xml` 등 제품 코드 | 문서 01~12 정리(M1 문서 기준선, 11/13) |
| FRONTEND | `src/main/resources/static/**`, `assets/`, `docs/` | Java 코드, `pom.xml`, `config/`, `prompts/`, 실제 네트워크 호출 | 화면 완료(M2, 11/19). 권고 점검표 참고 |
| BACKEND | 전체. 화면 구조 변경은 06번 문서·ADR 선행 | `api-client.js`를 건너뛴 화면 직접 호출 | 실험 전 구간 점검(M3, 12/2) |
| RELEASE | 실험을 막는 결함 수정, 문서 | 신규 기능 | 발표 |

### "기능 없는 화면"의 정의
- HTML 더블클릭으로 열린다(서버·JDK·Node 불필요). 클릭과 화면 전환은 동작해 흐름을 따라갈 수 있다.
- 데이터는 `js/fixtures/` 고정값. 마스킹·AI·저장·타이머는 없다. 화면 안에 시안 표시는 두지 않고 발표 때 구두로 알린다(ADR-016). 단계·분기 전환은 주소 키로 한다(06번 11절 시연 주소 목록).
- 화면은 `api-client.js`만 호출. 백엔드 단계에서 데이터 출처만 fixtures → REST로 바꾼다(응답 형식은 05번).

### 강제 장치 (세 겹, 구현 완료)
1. `CLAUDE.md`: 작업 전 `docs/gates/PHASE`를 읽는다, 문서에 없는 기능은 만들지 않는다.
2. Claude Code 훅: `.claude/settings.json` PreToolUse → `scripts/check_phase.py --claude`. 단계에서 금지된 경로, `references/` 쓰기를 차단.
3. Git pre-commit: `.githooks/pre-commit` → 스테이징 경로 검사 + API 키 형식 검사. 클론 후 `git config core.hooksPath .githooks` 필요.
- **한계:** `--no-verify`나 설정 변경으로 우회할 수 있다. Bash 도구로 파일을 쓰는 경우 Claude 훅이 잡지 못한다. 혼자 하는 프로젝트의 실수 방지 장치이며 우회는 금지로 명시. 원격 저장소 서버 측 검사는 범위 밖.
### 단계 전환 절차
승인 기록은 없다(ADR-010). 1. 필요하면 아래 권고 체크리스트를 훑는다(비차단) → 2. 브랜치 `chore/phase-<다음단계>` 에서 `docs/gates/PHASE` 한 줄만 바꿔 `chore(phase): <요약>` 으로 커밋 → 3. PR → 사용자가 squash merge. 머지 후 선택적으로 태그(`docs-v1.0`, `ui-v1.0`, `exp-ready`). 브랜치·PR·작업 트리·푸시 검토 규칙은 `13-git-conventions.md`.

- 위 스파이크·Q2 항목은 ADR-009로 M1에서 이동했다. 승인 조건은 아니지만, 미충족 상태로 BACKEND에 들어가면 R1·R8·R16 위험이 커지므로 가급적 전환 전에 확인한다.

## 5. 일정 초과 시 축소 순서 (먼저 빼는 것부터)
1. 사용 현황 통계(Could)
2. 안내문 AI 초안 → 시드의 고정 안내문으로 대체
3. "알려진 오류·내 신고" 탭의 내 신고 부분 → 대장의 알림 미리보기로 시연
4. 대장의 필터·대표 결함 신규 생성 → 시드 결함에 연결만
5. `compatible` 어댑터·두 번째 공급자 완성도 → 구조만 유지, 1개 공급자 + Mock
6. 판정 업로드 → 엑셀에서 직접 집계
7. 대리 접수 → 시연 대본에서 제외

**끝까지 지키는 것:** 마스킹과 테스트, 접수 패널 A/B, 실험 측정과 CSV, Mock 모드, 대장 최소판의 상태 변경 + 알림 미리보기 1개 경로.


## S4 공동 대응 보완 (ADR-023)

문서 기준선 → 업무별 목록/상세와 AI 시연 → 대응 흐름 → 사례 보강 순으로 진행한다. 이번 구현은 FRONTEND만이며 PHASE 변경·백엔드·인증·단톡방 자동 연동은 제외한다.
