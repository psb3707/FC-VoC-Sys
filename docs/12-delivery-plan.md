# 12. 일정·게이트·위험·개발 순서

## 1. 개발 순서 (강제)
`DOCS` → **G1** → `FRONTEND`(기능 없는 화면) → **G2** → `BACKEND`(구현·연결) → **G3** → `RELEASE`(12/4~)

| 단계 | 할 수 있는 일 | 막는 일 | 종료 게이트 |
|---|---|---|---|
| DOCS | `docs/`, 규칙·훅 파일, `assets/`, Git 제외 `spikes/` | `src/`, `pom.xml` 등 제품 코드 | G1 문서 기준선 |
| FRONTEND | `src/main/resources/static/**`, `assets/`, `docs/` | Java 코드, `pom.xml`, `config/`, `prompts/`, 실제 네트워크 호출 | G2 화면 승인 |
| BACKEND | 전체. 화면 구조 변경은 06번 문서·ADR 선행 | `api-client.js`를 건너뛴 화면 직접 호출 | G3 실험 전 구간 통과 |
| RELEASE | 실험을 막는 결함 수정, 문서 | 신규 기능 | 발표 |

### "기능 없는 화면"의 정의
- HTML 더블클릭으로 열린다(서버·JDK·Node 불필요). 클릭과 화면 전환은 동작해 흐름을 따라갈 수 있다.
- 데이터는 `js/fixtures/` 고정값. 마스킹·AI·저장·타이머는 없다. 상단에 "화면 시안 – 실제 동작 안 함".
- 화면은 `api-client.js`만 호출. 백엔드 단계에서 데이터 출처만 fixtures → REST로 바꾼다(응답 형식은 05번).

### 강제 장치 (세 겹, 구현 완료)
1. `CLAUDE.md`: 작업 전 `docs/gates/PHASE`를 읽는다, 문서에 없는 기능은 만들지 않는다.
2. Claude Code 훅: `.claude/settings.json` PreToolUse → `scripts/check_phase.py --claude`. 단계에서 금지된 경로, `docs/gates/`, `references/` 쓰기를 차단.
3. Git pre-commit: `.githooks/pre-commit` → 스테이징 경로 검사 + API 키 형식 검사. 클론 후 `git config core.hooksPath .githooks` 필요.
- **한계:** `--no-verify`나 설정 변경으로 우회할 수 있다. Bash 도구로 파일을 쓰는 경우 Claude 훅이 잡지 못한다. 혼자 하는 프로젝트의 실수 방지 장치이며 우회는 금지로 명시. 원격 저장소 서버 측 검사는 범위 밖.
### 단계 전환 절차
1. 게이트 점검표 작성 → 2. 사용자가 `docs/gates/G*.md`에 승인 기록 → 3. 사용자가 직접 `docs/gates/PHASE` 값을 바꾸고 **`gate/*` 브랜치에서 커밋·PR**, 머지 후 Git 태그(`docs-v1.0`, `ui-v1.0`, `exp-ready`). 브랜치·PR·작업 트리·푸시 검토 규칙은 `13-git-conventions.md`.

## 5. 일정 초과 시 축소 순서 (먼저 빼는 것부터)
1. 사용 현황 통계(Could)
2. 안내문 AI 초안 → 시드의 고정 안내문으로 대체
3. "알려진 오류·내 신고" 탭의 내 신고 부분 → 대장의 알림 미리보기로 시연
4. 대장의 필터·대표 결함 신규 생성 → 시드 결함에 연결만
5. `compatible` 어댑터·두 번째 공급자 완성도 → 구조만 유지, 1개 공급자 + Mock
6. 판정 업로드 → 엑셀에서 직접 집계
7. 대리 접수 → 시연 대본에서 제외

**끝까지 지키는 것:** 마스킹과 테스트, 접수 패널 A/B, 실험 측정과 CSV, Mock 모드, 대장 최소판의 상태 변경 + 알림 미리보기 1개 경로.
