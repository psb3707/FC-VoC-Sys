# 전산 오류 지원·경과 안내 PoC 기준선

상태는 검토용이다. 첨부 요구사항 v1.0의 UX-01~11과 TC-01~22에 대응한다. [ADR-024](../adr/ADR-024-intake-support-journey-poc.md)의 가상 정책을 구현 전에 확정한다.

## 단계와 화면

| 단계 | 기존 진입점 | 변경 | 수용 기준 |
|---|---|---|---|
| 2. FC 지원·대리 접수 | S1 퀵메뉴 → S2 접수 패널 | 문제 입력 화면에 긴급 도움과 사람 지원을 인라인으로 배치. 가상 AI 안내에서 조치·수정·다음 행동을 구분하고, 지원 요청 시 안전한 인계 요약 제공. 확인 화면에서 영향 FC·접수자·수신 대상·시도 결과 표시. 완료 화면에 접수번호, 확인 대기, 상세 열기 제공 | TC-01~10 |
| 3. IT 처리·FC 알림 | S4 결함 대장, S1 알림 팝업, S3 내 접수내역 | IT 인수 및 수동 연결, 승인 조치와 수정 정보 등록, 역할별 알림 미리보기 및 가상 기록. FC 상세에 문의 처리·업무 재개·결함 개선·다음 안내를 나누고 이력은 접힌 영역에 표시. 기존 추가 내용·재발 기록 유지 | TC-11, 13~18, 21 |
| 4. 관리자·통합 시연 | S3 기존 패널과 S1 알림 | 부지점장은 본인 대리 접수 및 담당 FC 현황을 필터링하고 직접 안내·추가 지원을 기록. 지점장은 영업 차질 신고 수, 영향 FC 수, 우선 조치 필요 결함 수, 주요 오류 3건과 승인 공통 조치 확인. 기존 홈에 새 메뉴를 두지 않음 | TC-12, 19 및 전체 통합 검증 |

착수 전 화면 요소를 [UI 명세 0-3절](../06-ui-spec.md)의 홈 대응표에 매핑한다. 긴급 도움·문의 대상·경과는 콘텐츠 카드, 이력·지원 경로는 접힌 영역, IT 등록은 기존 상태 변경 확인창, 역할별 알림은 기존 알림 패널을 사용한다.

## 역할과 시연 데이터

- FC는 자신의 문의와 공개 안내만 조회한다. 부지점장의 대리 접수 선택 대상은 같은 지점의 명시적 담당 FC로 제한한다. 부지점장 상세 조회는 본인이 접수한 건 또는 명시적 담당 범위에 한정한다. 상세 주소 직접 열기, 알림 읽음, 후속 기록 API에도 동일한 권한을 적용한다.
- IT는 미연결 업무 큐에서 인수 후 대표 결함을 선택해 연결한다. 기존 영업팀 대장 동작을 유지한다. 지점장에게는 자신이 속한 지점의 집계, 승인 공통 조치, 확정된 일정만 제공한다. 집계에는 개별 FC 식별자, 접수 상세 주소, 고객·계약 데이터와 자유 입력을 포함하지 않는다.
- 기존 `role=MANAGER` 주소는 부지점장 fixture를 사용한다. 기존 역할 전환 방식에 지점장용 가상 선택을 추가한다. 전자서명 시연을 명시적으로 선택했을 때만 별도 저장 영역을 열고 `D-2026-001`을 `CAUSE_FOUND`에서 시작한다. 기존 주소와 fixture의 `WORKAROUND` 상태는 변경하지 않는다.
- 같은 지점에 담당 FC 두 명과 권한 밖 FC, 부지점장, 지점장, IT fixture를 사용한다. 기본 시연에서는 부지점장이 두 FC를 대신 접수한 뒤 IT가 두 건을 같은 결함에 연결한다. 적어도 한 건에서 업무 중단을 명시해 지점장 알림의 가상 조건을 충족한다. 권한 밖 대상을 조회하는 경우와 지점장 기준 미충족 사례도 재현한다.
- 사람 지원 연락처 fixture의 기본값은 빈 목록이다. 승인된 연락처가 구성된 경우에만 표시한다. 인수·다음 안내 시점은 IT가 직접 기록한다. 대리 접수 알림 수신은 PoC fixture의 가상 전제이며 운영 동의·권한 정책은 후속 검토 사항이다.

## 프론트 데이터 계약

| 책임 | ApiClient에서 제공할 동작과 상태 |
|---|---|
| S2 접수 | 기존 접수·초안·질문 메서드 재사용. 지원 채널 조회, 권한 범위의 대리 접수 대상 조회, 가상 응답의 근거·공개 여부 제공. 마스킹한 인계 요약을 화면에서 확인·복사 |
| S3 경과 | 문의 ID와 현재 가상 세션으로 접수자·인수 근거·공개 조치·확정 일정·후속 이력 조회. FC 조치 결과를 RESUMED / UNRESOLVED / UNKNOWN 이력으로 추가. 접수 전 입력과 시도 결과는 메모리에서 접수 양식으로 이어 전달 |
| S4 대장 | 기존 결함 연결·상태 미리보기·저장·재시도 확장. 인수 시각은 명시적 인수 때 기록. FIX_PLANNED 전환은 확정 날짜 필수. 동일 상태에서 일정 변경은 별도 이벤트와 사유로 기록하고 일정 취소 시 미정 표시. RESOLVED는 적용 시각·범위·기존 건 조치, WONT_FIX는 승인 사유와 대안 필요 |
| S1 알림·관리자 | 현재 사용자 범위의 알림·읽음·대리 문의·지점 집계 조회와 직접 안내 또는 추가 지원 기록. 담당자 지정, 처리 등급, 수신자와 결함 연결을 AI 응답으로 확정하지 않음 |

기존 저장 상태에 새 구조의 기본값을 채운다. 자유 입력 원문과 가림 전 첨부는 기존 메모리 경계를 유지한다. 기존 구조화 진단·확정 가림 이미지 처리 규칙을 재사용한다. 화면은 저장소와 fixtures를 직접 읽거나 쓰지 않는다.

## 시연 알림 정책

| 사건 | FC | 부지점장 | 지점장 |
|---|---|---|---|
| 접수·인수 | 대리 접수 시 알림 1건. 인수는 상세만 갱신 | 본인 대리 접수 완료 화면·내역. 인수는 내역 갱신 | 없음 |
| 승인 임시조치 게시·수정 계획 확정 또는 변경 | 관련 FC마다 알림 1건과 현재 가능한 행동. 날짜 변경 시 이전·새 확정 일자 표시 | 본인 대리 접수 및 명시적 담당 FC를 결함 단위로 묶어 1건 | 승인된 공통 조치 게시 또는 중요한 일정 변경이면서 중대 기준 충족 시 지점 요약 1건 |
| 해결·수정하지 않음 | 적용 범위와 확인 요청, 또는 승인 사유와 대안 | 관련 FC 묶음 1건 | 해결 시 요약 갱신. 수정하지 않음은 중대 기준 충족 시 요약 |
| 조치 후 미해결·재발 | 본인 상세·이력 갱신 | 후속 지원 표시·관련 이력 | 중대 기준에 해당하는 경우 집계에 반영 |

중대 기준은 같은 지점·결함에 영향 FC가 두 명 이상이며 업무 중단이 기록된 경우다. PoC에서 확정 수정일의 이동·취소는 중요한 일정 변경으로 본다. 확정 일정이 없으면 미정으로 표시한다. 실질적 행동 변화가 없는 안내문 수정만으로 반복 알림을 생성하지 않는다. 재현 확인·원인 파악·되돌림은 내부 이력으로 남긴다. 재발·미해결은 IT/영업 지원 큐에서도 확인한다.

알림에는 제목, 변경 사실, 지금 할 일, 시각과 상세 이동 대상을 제공한다. 접수 상세·부지점장 목록·지점 요약으로 역할에 맞게 이동한다. `eventId + recipientId + notificationKind`로 재처리를 막고, 같은 사용자에게 동일한 의미의 개인·묶음 안내가 겹치면 한 건으로 표시한다. 부지점장 묶음 집계는 결함·FC별 중복을 제거한다. 실패한 수신자만 재시도하며 결함 상태와 성공 수신 기록은 보존한다. 배지는 읽지 않은 중요·행동 필요 알림만 센다.

## 수용 기준

| ID | 확인 방법과 기대 결과 |
|---|---|
| TC-01·02 | 업무·설명 입력 후 긴급 도움 열기. 입력은 유지되고 지원 경로가 비어 있어도 직접 접수 가능 |
| TC-03·04·05 | 승인된 안내의 임시조치·수정 상태 구분. 실패 선택 시 같은 조치 반복 없이 접수·지원으로 이동. 재개 선택 시 FC 결과만 변경하고 결함 참여는 명시적 동의로 진행 |
| TC-06·07 | 가상 AI 조회 실패 후 일반 접수·지원 가능. 정상 안내에서 업무·설명·시도·긴급 맥락을 확인 화면으로 옮기고 미확인 값은 미확인으로 표시 |
| TC-08·09·10 | 부지점장 대리 접수 후 다른 접속 역할로 상세와 접수 확인 비교. 권한 밖 FC 선택·직접 주소 접근을 차단하고 인수 전에는 대기 표시 |
| TC-11·12·13 | 승인 조치 미리보기와 저장 후 수신 대상·내용 일치. 동일 결함 FC 3명 대리 접수 후 FC별 1건과 부지점장 묶음 1건. 동일 이벤트 재처리 시 이력·알림 각 1회 |
| TC-14·15 | 날짜 미정, 확정 날짜 변경, 확정 일정 취소를 각각 검증. 근본 수정일과 다음 안내 일시를 구분 |
| TC-16·17·18 | 해결 적용 범위·후속 조치와 수정하지 않음 사유·대안 표시. 알림 읽음만으로 FC 업무 재개·부지점장 직접 안내 기록이 바뀌지 않음 |
| TC-19 | 지점장 요약의 중대 기준 충족·미충족 비교. 집계 화면과 가상 응답에 고객·계약 식별정보 및 신고 원문 없음 |
| TC-20 | 기존 숫자 단계 및 `known=off`의 A/B 진입, AI 숨김 조건, 분기, 제출·측정 경계를 변경 전후 대조 |
| TC-21 | 알림 실패 후 결함 상태 유지. 실패 수신자만 재시도하고 성공 화면은 기록이 성공했을 때 표시. 새로고침 후 이력 유지 |
| TC-22 | 1280·1888·1920px에서 화면 겹침·잘림 검사. 키보드 조작·초점 복귀·모션 줄이기를 확인 |

각 기능 PR에서 관련 시나리오와 기존 접수·대장 테스트를 실행한다. 통합 PR에 TC별 결과, 가상 데이터 화면 캡처, 미해결 항목을 기록한다. 기존 브라우저 검증은 `scripts/ui_check.py`, `scripts/intake_followup_check.py`, `scripts/intake_second_phase_check.py`를 사용한다.
