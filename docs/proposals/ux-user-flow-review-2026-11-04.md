# 화면 개선 구현·검토 결과 (2026-11-04)

별도 작업 트리 ux-user-flow / feat/req-in-04-ux-user-flow에서 사용자 피드백을 반영했다. 결정은 ADR-017. 현재 FRONTEND 단계이며 서버·실제 AI·실제 개인정보 처리·외부 발송은 구현하지 않았다. 기존 S4 작업 트리를 가져오지 않았다.

## 변경
- B 8→6단계, A 7→5단계. 자동 정보/전달 내역 통합, 짧은 요약과 선택적 수정.
- 입력·추가 답변·최종 수정 내용 보존, 완료→동일 내 신고 바로가기.
- 작성 중 닫기 확인, 새로고침 탭 초안 복원, 이중 제출 방지·실패 재시도.
- 알려진 오류 직접 공감, 사용자별 중복 방지·누적 건수 일치.
- 내 신고 상태/우회법 반복 제거, 상세·끝난 건·알림 이력 접기, 대리 접수 묶음.
- 알림 읽음과 미확인 배지. 가상 상태는 브라우저 탭 세션에만 유지.

## 개발·검토 분담
접수 화면과 데이터/경과 화면은 두 전문 개발 서브에이전트가 구현했다. 주 에이전트는 Playwright MCP로 사용자 흐름을 조작하고 미흡한 부분을 수정했다. 독립 디자인 리뷰어는 소스·캡처를 직접 확인하고 주 에이전트의 계산 스타일 실측값을 검토했다(리뷰어 컨텍스트에는 Playwright 도구 없음).
검토 후 해결된 신고의 이전 우회법·예정일 숨김, 수정한 제목/상세 설명의 조회 반영, 제출 중 잠금/재시도, 수정 요약 갱신을 보완했다.

## 검증
- 기존 scripts/ui_check.py와 동일한 93개 상태/화면 크기 조합을 Playwright MCP 재사용 브라우저로 실행: 93/93 PASS. 1024/1280/1888/1920 폭 포함. 글자·버튼 크기, 대비, 잘림, 기존 SFA 토큰 검사.
- 원래 python scripts/ui_check.py 전체 실행은 Chrome 반복 기동이 과도하게 느려 중단했으며 해당 CLI 완료를 주장하지 않는다. 정적 검사 함수는 따로 실행해 위반 0건 확인했다.
- Node 구문 검사, git diff --check 통과.
- 실제 조작: 임의 가입설계 설명/재현 답변 보존, 질문 중 새로고침 복원, 완료 R-201→같은 신고 조회, A모드 5단계/미분류, Escape 계속/폐기, S3 공감 7→8 및 새로고침 유지/재신고 금지, 알림 3→2, 관리자 대리 접수 조회, 최종 편집 제목/설명 조회, 요약 접기 갱신 통과.
- 지연 Promise로 빠른 제출2회→postReport1회 확인. 실패 Promise로 오류 안내/버튼 복구/재시도 성공 확인. 주입은 검토 브라우저에서만 수행했고 소스에는 없다.
- 디자인: 1280×800·1888×952에서 캡처 눈점검. 패널520px, 본문18px, 주요 버튼56px, 카드24px/기존 그림자. 강조색 대비4.90:1. 완료 차단 지적 없음. S2 독립 펼침과 S3 내부 펼침의 배치 차이는 문서화했다.
- 최종 확인 브라우저 콘솔 오류0건.

## 미리보기와 한계
로컬 서버가 실행 중일 때 http://127.0.0.1:8766/index.html 로 확인한다. HTML 직접 열기도 가능하다. 상태를 초기화하려면 새 브라우저 탭 세션을 사용한다.
캡처는 target/design-review/에 있다. 실제 결함 처리 순환(S4→알림), AI 분류 성능, 실제 개인정보 마스킹은 이 화면 작업의 검증 범위가 아니다. main과 기존 worktree의 제품 소스는 변경하지 않는다. 푸시·머지하지 않는다.
