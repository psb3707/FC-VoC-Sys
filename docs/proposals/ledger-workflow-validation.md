# 업무 문의·오류 관리 화면 구현·검증 기록

- 브랜치: `feat/ledger-workflow`
- 기준: ADR-023, `ledger-workflow-improvement.md`
- 단계: FRONTEND. 실제 LLM 호출·백엔드·인증·자동 발송 없음.

## 구현 범위

- 업무별 검토 대기 접수·진행 건·처리 사례, 담당 범위와 대기·재확인·확인일 경과 조건.
- 4열 업무 목록과 760px 상세. 업무 영향·담당·다음 조치·현장 공유를 앞세우고 근거·관련 접수·이력은 펼침으로 제공.
- 신규 관리 건 등록, 추가정보 요청, 담당 변경·IT 협조, 내부 확인 기록, 안내 후 종료, 재검토, 연결 해제·재연결.
- 현장 공유 초안 확인·복사·별도의 공유 완료 기록. 자유 서술은 현재 페이지 메모리에서 유지.
- AI 질문·예시·업무 범위·고정 답변·출처·적용 조건 비교·참고 연결, 없음·오래됨·조건 불일치·지연·실패.
- 기존 상태 변경·알림 미리보기·해결 안내·FC 내 신고·진단·첨부 경로 유지.

## 검증

| 검사 | 결과 |
|---|---|
| 정적 검사: 외부 통신·금지 표현·가상 데이터 형식 | PASS |
| `python scripts/ui_check.py ledger` | 53개 주소 × 3개 크기 = 159/159 PASS |
| `python scripts/ui_check.py index` | 기존 S1~S3 99/99 PASS, 접수 복구·재시도·내역 연결 및 AI 모션 동작 PASS |
| `scripts/ledger_workflow_browser_check.js` | 최종 변경 반영 후 31/31 과업·회귀 검사 PASS, pageerror 0 |
| 디자인 일관성 검토 | 토큰·여백·4열 표·760px 상세 확인. 지적 3건 수정 완료 |

31개 검사는 업무 집계, 필터 포커스, 입력 초안, 추가 요청, 사람 확인, 종료·재검토, AI 출처·비교·참고 연결, 실제 접수 연결·해제, 상태 알림, FC 이전 안내 제거, 신규 등록·협조, 자유 서술 영구 저장 제외, AI 5개 분기와 1024/1280/1920 레이아웃을 포함한다.

전체 화면 검사는 최종 연결 완료·FC 연결 해제 회귀 수정 전에 수행했고, 해당 수정 이후에는 31개 실제 과업 검사로 변경 경로를 재검증했다. 이는 실제 사용자 평가·모델 품질·운영 보안 검증을 대체하지 않는다.

## 디자인 검토 보완

1. 필터·검색을 다시 그려도 포커스를 유지. AI 열기→질문, 닫기→진입점 복원.
2. 기존 관리 건 연결을 AI 펼침 밖의 고정 행동 영역에도 노출.
3. 시각을 한국 시간으로 표시. 접수 시각과 실제 발생 시각을 혼동하지 않도록 이름을 구분.

## 실행·재현

- 정적 화면: `src/main/resources/static/ledger.html`을 브라우저에서 연다.
- 역할: `#role=SALES` 또는 `#role=IT`. 전체 업무: `business=ALL`.
- AI: `#role=SALES&ai=1`에서 예시 질문을 누른다. 분기: `llm=slow|fail`, `aiCase=empty|old|mismatch`.
- UI 자동 검사: 저장소 루트에서 `python scripts/ui_check.py ledger`, `python scripts/ui_check.py index`.
- 과업 검사: 정적 폴더를 localhost로 제공하고 해당 S4 탭을 연 뒤 Playwright MCP의 `browser_run_code_unsafe`에 `scripts/ledger_workflow_browser_check.js`의 절대 경로를 filename으로 전달한다. 독립 브라우저 컨텍스트를 사용한다.

## 제한과 후속

- AI는 질문 표현에 맞춘 고정 사례 응답이다. 실제 AI 연결·검색 정확도는 후속이다.
- 신규 제목·내부 기록·공유 초안 등 서술 입력은 새로고침하면 사라진다. 화면에 이 제한을 설명하며 구조화 시연 상태는 브라우저에 남을 수 있다. 영구 데이터 보존은 구현하지 않았다.
- 업무 담당은 가상 매핑이다. 실제 업무 분장·지점 직접 사용·공유 책임 확인 후 운영 설계로 전환한다.
- 공용 상태 코드를 단순 치환하지 않았다. 기존 FC 표시는 기존 코드에 따르고 관리자 업무 상태는 별도 메타데이터다.
- 메시지 붙여넣기 초안·AI 추가질문 생성·개인 기본 설정은 계획의 후속 선택 범위로 남긴다.

## ADR-024 대응 중심 안내 개선

- 진입점은 ‘이전 처리 방법 찾기’, 열린 제목은 ‘어떻게 대응하면 될까요?’로 변경했다.
- 가장 관련 있는 핵심 답 하나를 먼저 표시하고, 먼저 확인할 항목·조건별 대응·근거 기록 순으로 구성했다. 다른 증상과 상세 기록은 기본 접힘이다. 답변 뒤 예시 질문은 숨겨 불필요한 반복을 줄였다.
- 모호한 서명 질문은 ‘다른 화면’과 ‘화면 멈춤’ 중 선택해 좁힌다. 조사 중·과거 조치·조건 불일치에는 확정된 해결책처럼 안내하지 않는다.
- 특정 접수에서 시작하면 현장 안내 초안과 확인 요청 내용을 별도 양식으로 가져온다. 조건을 보존하고 공유 확인은 해제된 상태로 시작한다. 가져오기만으로 저장·발송·상태 변경하지 않는다.
- 검증: 정적 PASS, S4 화면 159/159 PASS. 기존 31개 업무 흐름 PASS. 신규 `scripts/ledger_guidance_browser_check.js` 최종 30/30 PASS(1024/1280/1920 답변 표시 상태 자체 검사 포함), pageerror 0.
- 디자인 재검토의 예시·증상 선택 후 포커스 유실 1건을 수정하고 신규 검사에 추가했다. 별도 검토자는 PNG·JS·CSS와 자동 검사 결과로 확인했으며 별도 MCP 브라우저는 프로필 점유로 열리지 않았다.
- 전체 화면 검사 뒤 답변 후 예시 숨김·과거 기록 문구·포커스를 보완했고, 최종 30개 안내 흐름 검사로 변경 경로를 재검증했다. 실제 AI API와 모델 성능은 이번에도 검증 범위 밖이다.
- 신규 검사 재현: 기존 S4 탭을 연 Playwright MCP의 `browser_run_code_unsafe`에 `scripts/ledger_guidance_browser_check.js` 절대 경로를 filename으로 전달한다. 독립 컨텍스트에서 실행하므로 사용자의 시연 상태를 초기화하지 않는다.
