# ADR-006. 문서 → 기능 없는 프론트 → 백엔드 순서로 강제한다
- 상태: 승인 (사용자 지시, 2026-11-02)
- 일부 대체: ADR-010 (게이트 승인 절차 폐지)
- 배경: 이 프로젝트는 바로 개발에 들어가지 않고 확실한 문서화를 의사결정 기준으로 삼는다. 개발은 기능이 동작하지 않는 프론트 화면부터 보이게 하고 이후 백엔드를 만들어 연결한다.
- 결정: 단계 DOCS → FRONTEND → BACKEND → RELEASE, 게이트 G1·G2·G3. `docs/gates/PHASE` + `scripts/check_phase.py`로 Claude 훅과 Git pre-commit에서 강제. 게이트 파일은 사용자만 수정.
- 영향: 12번 문서 1절, `CLAUDE.md`. 일정에 fixtures·화면 검토 비용 추가, 실험 전 구간 점검이 12/2로 이동(버퍼 0.25pd).
- 한계: 훅은 우회 가능(`--no-verify`, 설정 변경, Bash 직접 쓰기). 혼자 하는 프로젝트의 실수 방지 장치.
