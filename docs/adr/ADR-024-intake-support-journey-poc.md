# ADR-024. 전산 오류 지원·대리 접수·경과 안내 PoC

- 상태: 제안 · 1단계 검토용
- 범위: FRONTEND, UX-01~11. UX-12 외부 채널 연동은 후속 범위.
- 관련 결정: ADR-014, ADR-015, ADR-017~019, ADR-021~022
- 화면·데이터 계약 및 수용 기준: [전산 오류 지원·경과 안내 PoC 기준선](../proposals/poc-intake-support-journey.md)

## 배경

전자서명 오류를 대신 접수한 부지점장과 실제 영향을 받은 FC는 같은 접수의 경과를 각자 확인할 수 있어야 한다. 임시조치로 업무를 재개할 수 있는지, IT 담당자가 문의를 인수했는지, 대표 결함의 수정이 어디까지 진행됐는지는 서로 다른 사실이다.

## 제안

1. 기존 SFA 홈과 두 화면 접수를 사용한다. 긴급 도움과 사람 지원은 인라인으로 열고 건너뛸 수 있게 한다. 가상 AI 안내에서 승인된 조치, 공개된 수정 상태, 다음 행동을 구분한다. 기존 입력을 접수 확인 화면에 넘기고 마스킹된 인계 요약만 복사할 수 있게 한다.
2. 가상 사용자 fixture의 MANAGER에 DEPUTY / BRANCH_HEAD를 부여하고 담당 FC 관계를 명시한다. 대리 접수에는 실제 FC와 접수자를 구분해 기록한다. IT가 인수와 결함 연결을 직접 확정한다. 접수 상태, FC의 조치 결과, 결함 상태, 확정된 다음 안내 일시는 독립적으로 관리한다.
3. 상태·권한·알림은 기존 ApiClient의 가상 계약을 확장한다. IntakeDemoStore와 fixtures로 같은 브라우저의 SFA·대장 화면에 구조화 상태를 공유한다. 일반 fixture와 숫자 단계 시연 주소를 그대로 쓰고, 전자서명 end-to-end 시연은 명시적으로 선택한 별도 상태에서 수행한다. 운영 인증·서버·DB·외부 API·실제 발송은 후속 범위다.
4. 접수 확인·담당자 인수는 문의 단위 이벤트다. 대리 접수 건은 FC에게 접수 알림 1건을 생성하고 대리 접수자에게 완료 화면과 내역을 제공한다. 인수는 내역만 갱신한다. 승인된 조치와 주요 결함 변경은 FC별 알림 및 부지점장별 결함 묶음 알림을 만든다. 지점장은 가상 중대 기준에 해당하는 경우에만 비식별 요약을 받는다. 알림 읽음, FC의 업무 재개, 부지점장의 직접 안내 기록을 독립적으로 저장한다.
5. 같은 이벤트에서 미리보기와 확정에 같은 수신 규칙을 쓴다. 미리보기 이후 대상 또는 본문이 바뀌면 확정 전에 다시 보여준다. 확정 시 수신자와 메시지를 기록하고, 실패한 가상 알림만 같은 이벤트로 재시도한다. 재시도 때문에 상태 이력과 이미 생성된 알림이 중복되지 않게 한다.

## 기존 결정과의 영향

| 기준 | 적용 |
|---|---|
| ADR-014·015 | 기존 홈·패널 진입점과 토큰 사용. 문의 상태 배열을 바꾸되 기존 결함 이력과 후속 기록은 패널 안에서 유지 |
| ADR-017 | 가상 유사 결함 결과는 후보. 결함 연결과 문의 인수는 IT의 명시적 행동. 기존 대장 신규 신고 큐 유지 |
| ADR-018·019 및 실험 프로토콜 | 기존 두 화면과 직접 접수 경로 유지. S5의 `known=off`, A모드 AI 숨김, 숫자 단계 주소, 측정 경계와 시나리오 fixture는 기존 조건 유지 |
| ADR-021 및 도메인 규칙 §4 | 사용자별 1건 및 실패 재시도를 유지. 대리 접수 및 관리자 수신을 추가하고 같은 상태에서 확정 일정이 바뀐 경우를 주요 이벤트로 추가. 재현 확인·원인 파악·되돌림은 기존대로 내부 이력. 임시조치 안내는 승인된 원문만 공개 |
| ADR-022 및 개인정보 기준 | 확정 가림 전 이미지·파일명과 자유 입력 원문은 공유 저장소 및 가상 AI 경로에서 제외. 기존 허용 목록과 가림 검증을 재사용. 지점장 응답은 집계용 필드만 제공 |

## 검토 및 반영

이 ADR과 연결된 문서에서 가상 담당 관계, 인수·다음 안내의 기록 주체, 지점장 요약 범위·수신 기준, 대리 접수 알림 조건을 검토한다. 운영의 권한·동의·지원 채널·안내 약속은 별도 결정 사항으로 남긴다. 사용자 검토 결과를 ADR 및 요구사항·도메인·데이터·화면·개인정보 문서에 반영한 뒤 기능 PR을 진행한다.
