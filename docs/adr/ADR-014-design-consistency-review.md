# ADR-014. 새 화면의 디자인 일관성 검증 절차 (착수 전 대응표 + 완료 후 실측 비교)
- 상태: 승인 (사용자 지시, 2026-11-03 "디자인 톤이 어긋나는 문제를 사전에 검증·개선하는 워크플로우를 문서로 남겨라")
- 보완: ADR-011 결정 1(시각 스타일), `06-ui-spec.md` 11절(화면 검증 절차)

## 배경
- S2 접수 패널은 자동 검사(`ui_check.py`: 글자·버튼 크기, 대비, 넘침)를 모두 통과했지만, 홈 화면과 나란히 보면 디자인 톤이 달랐다.
  - 카드: 홈은 테두리 없음 + 모서리 24px, 패널은 1px 테두리 + 16px
  - 안내 상자: 홈에 없는 왼쪽 굵은 띠
  - 보조 버튼·칩 테두리 네 종류, 단계 막대 색 겹침, 글자 간격(홈 -0.448px, 패널 0)
- 화면을 다 만든 뒤 서브에이전트로 실측 비교해서야 발견했고, 고치는 데 PR 한 번이 더 들었다(#7 안의 후속 커밋).
- 원인: 자동 검사는 **접근성 하한**만 보고, **홈과 같은 시각 언어인지**는 보지 않는다. 새 요소마다 "홈의 어느 요소를 따르는가"를 정하지 않고 만들었다.

## 결정
1. **착수 전 – 디자인 대응표.** 새 화면(또는 새 요소)을 만들기 전에, 쓰려는 요소마다 `06-ui-spec.md` 0-3절 "홈 디자인 대응표"의 어느 행을 따르는지 정하고 PR 본문에 적는다. 표에 없는 모양이 필요하면 먼저 0-3절에 행을 추가한다(값은 홈 실측 또는 `sfa-tokens.css` 변수).
2. **값은 토큰에서만.** 새 화면 CSS는 색·모서리·그림자·글자 간격을 직접 쓰지 않고 `sfa-tokens.css`·`app.css`·화면별 토큰(예: `--pn-*`)을 거친다. 접근성 기준(0-2절: 18px·56px·`#0077b3`)과 홈 모양이 부딪히면 접근성 기준이 우선이고, 모양(모서리·그림자·테두리 유무·색 계열)은 홈을 따른다.
3. **완료 후 – 실측 비교.** 자동 검사 통과 뒤, 디자인 일관성 리뷰어(`.claude/agents/design-consistency-reviewer.md`, 읽기 전용 서브에이전트)가 Playwright로 홈과 새 화면의 계산 스타일을 실측해 0-3절과 비교하고, 어긋남·시각 버그·잘 맞는 점을 보고한다. 지적 사항은 같은 PR에서 고치고 자동 검사를 다시 돌린다.
4. **PR 체크리스트**에 "디자인 대응표 작성", "일관성 리뷰 지적 반영" 항목을 둔다.
5. 결함 대장(S4)·실험(S5)·진행자(S6)는 SFA 밖 화면이라 SFA 모양을 흉내 내지 않는다(0절 원칙 3). 대신 **S2 패널이 만든 새 요소 토큰(0-2절, `--pn-*`)을 서로 같게** 쓰고, 리뷰어는 홈 대신 S2 패널을 기준으로 비교한다.

## 대안(불채택)
- 자동 검사(`selftest.js`)에 모양 일치 검사 추가: 모서리·그림자 같은 "톤"은 요소마다 기준이 달라 규칙으로 고정하기 어렵고 오탐이 많다. 대응표 + 사람/리뷰어 비교로 시작하고, 반복해서 어긋나는 항목만 나중에 자동 검사로 옮긴다.
- 화면 완료 후 사람이 눈으로만 확인: S2에서 이미 놓쳤다.
