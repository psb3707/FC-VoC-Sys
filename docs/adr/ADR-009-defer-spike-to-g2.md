# ADR-009. 스파이크 검증을 G1에서 G2로 이동한다
- 상태: 승인 (사용자 지시, 2026-11-02)
- 배경: 당분간 기능 없는 화면의 구조·디자인만 먼저 확인한다. 프론트 단계는 HTML 더블클릭으로 열리며(서버·JDK·Node 불필요) JDK와 LLM API 키가 필요 없다. 그런데 G1(11/13) 점검표에는 JDK·Maven 확인, 프록시 경유 LLM 실호출, 공급자 비교, 기술 버전 고정, Q2 확인이 들어 있어 화면 확인 전에 환경 준비를 요구한다.
- 대안:
  1. 그대로 G1 유지: 11/13까지 환경·LLM 검증. 화면 작업과 무관한 준비가 문서 기준선을 지연시킴.
  2. **G2(11/19) 통과 조건으로 이동**: 프론트 주간에 병행하고 PHASE를 BACKEND로 바꾸기 전에 충족.
  3. 백엔드 착수 직전(11/20)으로 이동: 게이트 조건이 아니라 착수 당일 확인. 실패 시 대응 여유가 없어 위험이 크다.
- 결정: 2안. 아래를 G1에서 빼서 G2 통과 조건으로 옮긴다. 3안은 위험이 커서 채택하지 않는다.
  - 스파이크: JDK/Maven Central 설치·접근 확인, 프록시 경유 LLM 실호출 확인, 공급자 비교, 기술 버전 고정(04번)
  - Q2(외부 LLM 허용 서비스·비용 처리) 확인
  - G1에 남기는 것: 문서 01~12 완성, Must 수용 기준·추적표, `sfa-main-masked.png` 제작과 영업팀 검토, 멘토 중간 보고, Q3·Q4 확인, 사용자·멘토 승인.
- 영향:
  - `12-delivery-plan.md`: G1·G2 점검표, 3절 일정(스파이크 1.5pd를 11/16~11/19 주간에 병행, 그 주 부하 증가), 4절 R1·R8 확인 시점, R16 추가
  - `04-tech-stack.md`와 ADR-003: 버전 확정 시점이 G1에서 G2로 이동
  - `01-requirements.md` 8절: G1·G2·Q2 기한
  - R1(프록시·승인 실패) 확인 시점이 G1에서 G2로 이동
- 위험: 환경 문제를 11/19에야 발견하면 11/20 백엔드 착수가 지연된다. 완화: 스파이크를 프론트 주간에 병행하고 11/17까지 JDK 확보를 확인한다. JDK는 ZIP 배포판(`.tools/`) 대체를 허용한다. 실패 시 R1 대응(Mock + 규칙 되묻기, "AI 시뮬레이션" 명시)을 G2에서 결정한다.
- 되돌림 조건: 프론트 단계 중 JDK·LLM 관련 승인(Q2)이 막혀 일정 영향이 확인되면 사용자 결정으로 해당 항목을 G1 또는 별도 기한으로 다시 올린다(새 ADR).
