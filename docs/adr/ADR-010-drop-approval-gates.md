# ADR-010. 게이트 승인 절차를 폐지하고 단계 순서 강제만 남긴다
- 상태: 승인 (사용자 지시, 2026-11-02)
- 배경: 사용자가 기능 없는 프론트 화면부터 보기를 원한다. 1인 PoC에서 승인 기록 파일, 승인자·승인일, 멘토·영업팀·사용자 sign-off을 단계 전환의 필수 조건으로 두는 것은 과하다. 사용자 지시: "승인절차를 전체 작업 워크플로우에서 배제해줘."
- 대안:
  - A. **순서 강제(문서 → 프론트 → 백엔드)는 유지하고 승인 절차만 폐지**: `PHASE` + `check_phase.py` 경로 검사는 그대로, 승인 기록·`gate/*` 브랜치·보호 규칙은 없앤다.
  - B. 순서 강제도 폐지: 단계 검사 없이 자유롭게 작업. ADR-006의 핵심 요구(문서 → 기능 없는 프론트 → 백엔드)를 잃는다.
  - C. 승인 유지·완화: 기록 양식만 간소화. 1인 PoC에서는 여전히 형식 비용이 든다.
- 결정: **A**.
  - 폐지: G1~G3 "승인", 승인 기록(`docs/gates/G*.md`)과 양식, 승인자·승인일·조건부 승인, 멘토·영업팀·사용자 sign-off의 단계 전환 필수화, `gate/*` 브랜치 유형과 "PHASE 변경은 `gate/*` 브랜치만" 규칙, `docs/gates/`·`PHASE`에 대한 Claude 수정 금지.
  - 유지: 단계 순서 강제(`PHASE` + `check_phase.py`), PR → squash merge, `main` 직접 커밋·푸시 금지, 머지는 사용자만, `references/` 보호, 커밋·브랜치·푸시 검토 훅.
  - 변경: 단계 전환은 일반 PR로 한다. 브랜치 `chore/phase-<다음단계>`, 커밋 `chore(phase): <요약>`, `PHASE` 한 줄만 바꾼다. 기존 점검표(스파이크 포함)는 **비차단 권고 체크리스트**로 남긴다.
  - 용어: "게이트(G1~G3)"를 "마일스톤 M1~M3"로 바꾼다. M1 문서 기준선(11/13), M2 화면 완료(11/19), M3 실험 전 구간 점검(12/2). 날짜는 일정 지표로만 쓴다. `01-requirements.md` 8절의 가정 ID(G1~G8)는 마일스톤이 아니므로 그대로 둔다. 주석 태그(`docs-v1.0`, `ui-v1.0`, `exp-ready`)는 필수가 아닌 선택 표식이다.
- 영향:
  - ADR-006의 게이트 승인 부분, ADR-008의 `gate/*` 브랜치, ADR-009의 G2 통과 조건이 비차단 권고로 바뀐다. 해당 ADR 본문은 역사 기록으로 둔다.
  - `00-index.md`, `01`·`03`·`06`·`11`·`12`·`13`번 문서, `CLAUDE.md`, `scripts/check_phase.py`, `scripts/check_git_rules.py`, PR 템플릿 갱신. `docs/templates/gate-template.md` 삭제.
  - 파일 경로 `docs/gates/PHASE`는 유지한다. 이름 변경은 별도 작업.
- 위험: 환경 미비(JDK·Maven·프록시 LLM 호출)를 늦게 발견할 수 있고, 문서 품질 점검이 생략될 수 있다. 완화: 비차단 권고 체크리스트를 유지하고 R16(스파이크 지연) 대응을 그대로 둔다.
- 되돌림 조건: 승인 누락으로 일정·품질 문제가 확인되면 사용자 결정으로 새 ADR을 써서 일부 또는 전부를 복원한다.
