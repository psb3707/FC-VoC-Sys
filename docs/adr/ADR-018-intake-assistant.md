# ADR-018. 전산 오류 접수에 AI 문의 추가

- 근거는 2026-11-06 사용자의 설계사 피드백과 접수 화면 요청이다.
- REQ-IN-11은 ADR-017에서 보류한 S2 사전 문의를 별도 선택 화면으로 도입한다. ADR-017의 S4 신고 묶기 규칙은 그대로 적용한다.

## 결정

1. S2 알려진 오류 화면 상단에서 [AI에게 물어보기]를 연다. 추천 질문을 바로 보내거나 한 줄을 입력한다. S5 실험 경로(`known=off`)와 AI를 끈 A모드에서는 진입점을 숨긴다.
2. 사용법은 확인된 안내를 보여준다. 같은 증상의 공개 결함이 한 건이면 대장 번호와 현재 상태, 승인 안내문이나 공개된 임시 방법, 공개 예정일을 보여준다. 처리 중인 결함은 그 상태를 분명히 알린다. 공개 결함이 없거나 여러 건으로 판단하기 어렵거나 조회에 실패하면 담당자 확인으로 넘긴다.
3. [이 내용으로 문의 접수]는 작성 중인 질문을 기존 접수 양식의 한 줄 설명에 옮긴다. 업무·문제 유형은 알려진 경우에만 미리 고르고 설계사가 수정한다. 일반 접수의 고객 관련 여부 확인과 최종 제출은 설계사가 진행한다. 담당자 확인 경로는 시연용 AI 티켓과 되묻기를 거치지 않고 미분류로 넘긴다.
4. FRONTEND 단계에서는 가상 시나리오의 표현을 매칭하고 결함 대장의 가상 공개 필드를 읽는다. 질문을 주소나 브라우저 저장소에 넣지 않는다. 형식이 뚜렷한 번호·이메일 차단은 화면 시연에 사용한다.
5. BACKEND 단계에서는 원문 대신 기존 `MaskedInput`만 분류·검색 모듈에 전달한다. FC에게 공개된 필드만 별도 응답으로 보내며, 공개 여부와 안내문 승인은 서버에서 검증한다. 매칭 결과가 제출되더라도 기존 대장에 묶는 결정은 담당자가 한다.
