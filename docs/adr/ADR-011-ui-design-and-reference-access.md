# ADR-011. 화면 디자인 원칙과 참고 원본(references/) 접근 방식
- 상태: 승인 (사용자 지시, 2026-11-02 "모두 권장대로 진행, reference도 참고하도록 권한 수정")
- 일부 대체: ADR-005 (원본 미열람 → 마스킹된 구조 요약으로 참고)

## 배경
- PoC 청중은 임원이다. 기존 SFA에 익숙하므로 "새 시스템"이 아니라 "쓰던 화면에 창구 하나가 생겼다"가 가장 설득력 있다.
- 사용자는 기존 화면에 최소한만 추가하길 원했고, 디자인을 실제 SFA에 맞추려면 참고 원본을 볼 필요가 있다.
- 참고 원본은 로그인 상태의 실제 페이지라 실존 인물로 보이는 이름·번호·상품·설계 이력이 들어 있다. 원본을 그대로 읽으면 외부 LLM으로 전달되며(제안서 7.4 "가상 데이터만"과 충돌), 크기도 약 220만 토큰이라 통째로 읽을 수 없다.

## 결정 1. 화면 디자인 원칙
| 항목 | 결정 | 대안(불채택) |
|---|---|---|
| 진입점 | 기존 오른쪽 퀵메뉴와 **같은 모양의 글자 버튼 한 칸** "전산 오류 접수" | 작은 아이콘만(고령 FC·임원이 알아보기 어려움) |
| 경과 공유 | 상단의 **기존 알림 아이콘에 숫자 배지만** 추가 | 새 알림 요소 추가 |
| 기존 화면 추가 요소 | 퀵메뉴 버튼, 공지 탭 "알려진 오류·내 신고", 알림 배지 **세 가지로 한정** | 그 이상 |
| 시각 스타일 | 진입점은 기존 SFA 모양 그대로, 열리는 패널·결함 대장은 새 접근성 기준(18px·56px) | 패널도 기존 모양(12~14px) |
| 전·후 비교 | 프로토타입이 아니라 **발표 구성**(현재 흐름 장표 1장 → 같은 사례 목업 시연)으로 | 목업 안에 비교 화면 |
| 캡처 이미지 | 준비 전에는 레이아웃 블록으로 만들고, `sfa-main-masked.png`가 오면 교체 | 이미지 대기 |

## 결정 2. 참고 원본 접근
- Claude는 원본을 직접 읽지 않고 **`scripts/ref_outline.py`의 마스킹된 구조 요약만** 참고한다.
  - 영역: 상단 업무 메뉴, 상단 유틸리티(허용 목록 문구만), 오른쪽 퀵메뉴, 탭 제목, 관련 CSS 규칙.
  - 제외: 사용자 정보, 표(그리드), 달력, 슬라이드, 게시판 목록 등 데이터 영역.
  - 마스킹: 숫자 → `#`, 호칭 앞 이름·성씨로 시작하는 3글자 낱말 → `[이름]`/`[이름?]`, 회사·서비스 식별 문자열 → `[회사]`, `구분/이름/번호` 형태 행 → `[데이터 행]`, 25자 초과 → `[긴 문구]`.
  - **출력은 화면에 띄우기 전에 자동 검사**(성씨 3글자 잔여, 데이터 행, 회사명)를 통과해야 한다. 임시 출력 파일은 확인 후 지운다.
- 유지: 원본은 쓰기 금지(훅), Git 제외, 앱 미포함, 외부 공개 자료 미포함. 시드·평가 데이터로 값 복사 금지.

## 사고 기록 (2026-11-02)
- 요약 스크립트 첫 버전이 "탭" 영역에 표의 데이터 행(가입설계 이력)을 포함해, 이름으로 보이는 문자열 1개(2회)와 상품명·설계 이력 일부가 **가려지지 않은 채 Claude 대화에 전달**됐다. 저장소·파일에는 남지 않았다(임시 출력 삭제).
- 원인: 영역 탐지가 탭 본문까지 포함했고, 호칭 없는 이름을 가리는 규칙이 없었다.
- 조치: 데이터 영역 통째 제외, 탭은 제목만, 성씨 3글자 규칙·데이터 행 규칙 추가, 출력 전 자동 검사 절차 도입.

## 한계
- 규칙 기반 마스킹은 완전하지 않다. 영역을 넓히거나 새 영역을 추가할 때는 먼저 자동 검사만 실행해 결과를 확인한다.
- 캡처 이미지 가림 작업은 여전히 사람이 눈으로 확인해야 한다.
