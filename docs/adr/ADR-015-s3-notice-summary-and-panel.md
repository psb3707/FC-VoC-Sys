# ADR-015. S3 알려진 오류·내 신고 배치 (공지 카드 요약 + 오른쪽 패널)
- 상태: 승인 (사용자 결정, 2026-11-03)
- 보완: `06-ui-spec.md` 3절(진입점), 5절(S3), 11절(상태 주소), ADR-011(진입점은 기존 모양), ADR-014(디자인 대응표)

## 배경
- 06번 5절은 S3에 담을 내용(알려진 오류 목록, 내 신고 진행 단계·안내문, 알림 미리보기 내역)만 정했고, **어디에 어떻게 보여 줄지**는 정하지 않았다.
- 진입점인 공지 탭(5번째)은 기존 SFA 모양(14px, 공지 카드 높이 308px)이라 18px·56px 기준의 상세 내용을 카드 안에 다 넣을 수 없다.
- 알림 팝업의 "내 신고 경과" 항목도 같은 내용을 가리키지만 지금은 "다음 단계에서 만들어요" 안내 상자만 연다.

## 결정
1. **공지 카드에는 요약만.** 5번째 탭 "알려진 오류·내 신고"를 누르면 공지 카드 안의 목록 자리에, 기존 공지 목록 줄과 같은 모양(높이 48px, 14px, 오른쪽 작은 글자)으로 요약 줄을 몇 개 보인다.
   - `[내 신고] <제목>` · 오른쪽에 지금 상태(예: 임시조치)
   - `[알려진 오류] <제목>` · 오른쪽에 수정 예정일 또는 "수정하지 않음"
   - 요약 줄은 새 기능의 **진입점**이므로 `data-a11y="sfa"`로 표시한다(기존 모양 토큰 검사 + 대비 검사 대상, 18px·56px 검사 제외). 기존 공지 목록은 그대로 `replica`.
2. **자세한 내용은 오른쪽 패널.** 요약 줄을 누르면 S2와 같은 틀(폭 520px, 1280 미만 100%, 18px, 56px 버튼, `#0077b3`, 머리의 `#0099e6` 아이콘 원 + 제목 + 닫기)의 패널이 열린다. 패널 안에 [알려진 오류] [내 신고] 두 전환 탭.
   - 알려진 오류: 카드마다 제목, 지금 상태(글자), 임시 우회법, 수정 예정일 또는 고치지 않는 이유, 같은 신고 건수(REQ-KN-01).
   - 내 신고: 카드마다 단계 진행 표시(02번 3절 단계: 접수 → 재현 확인 → 원인 파악 → 임시조치 → 수정 예정 → 해결 / 수정하지 않음), 지금 상태를 **글자로**(색만으로 전하지 않음), 승인된 FC용 안내문(REQ-KN-02, REQ-NT-01: 승인본만). 아래에 알림 미리보기 내역(06번 5절 셋째 항목).
3. **알림 팝업 항목은 내 신고로.** 알림 팝업("내 신고 경과")의 항목을 누르면 이 패널이 [내 신고] 탭으로 열리고 해당 신고 카드로 이동한다. 그 밖의 "다음 단계" 안내(결함 대장 링크 등)는 그대로 둔다.
4. **상태 주소.** `board=known`(공지 카드 요약), `panel=known`(S3 패널), `tab=known|mine`, `item=<D-… 또는 R-…>`. `panel` 값은 하나라서 S2(`panel=intake`)와 S3는 동시에 열리지 않는다. S3를 열 때 S2 단계 키(`step`, `alert`, `case`, `proto`)를 지우고, S2를 열 때 `tab`, `item`을 지운다.
5. **문서에 없는 기능은 넣지 않는다.** "나도 겪었어요" 버튼은 06번 4절(S2 0단계)과 9절 흐름에만 있으므로 S3 패널에는 두지 않고, "'전산 오류 접수'에서 누를 수 있어요" 안내 문구만 둔다.
6. 단계 이름은 화면에서 쉬운 말로 쓴다: "재현 확인" → "문제 확인"(06번 1절 문구 기준). 나머지는 02번 이름 그대로.
7. **수정하지 않음 표시.** `WONT_FIX`가 된 신고는 진행 막대를 직전 상태까지만 채우고 "수정하지 않음 · ○○ 단계에서 끝났어요"로 글자로 알린다.
8. **데이터 형식.** `Defect.status` 코드와 `GET /api/reports/mine` 응답 형식은 05번 1절·4절에 추가한다.

5~8은 구현 후 사용자에게 확인받아 추천안대로 확정했다(2026-11-03).

## 대안(불채택)
- 공지 카드 안에 전부 표시: 14px 카드 안에 18px 상세를 넣을 수 없고, 넣으면 기존 화면 모양이 무너진다(0절 원칙 1).
- 별도 페이지: SFA 맥락이 끊기고, S2 패널과 다른 이동 방식이 생긴다.
