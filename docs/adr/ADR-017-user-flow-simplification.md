# ADR-017. 사용자 흐름 간소화와 브라우저 가상 상태 연결
- 상태: 채택 (사용자의 피드백 반영·별도 작업 트리 요청, 2026-11-04)
- 보완: ADR-015 2·5·8항, 01·05·06·11번 문서

## 배경
실제 조작에서 입력과 다른 고정 티켓, 접수 후 내 신고 누락, 공감 비누적, 닫기 입력 유실, 알림 고정, 상태·안내 반복을 확인했다. 사용자는 피드백 반영을 요청했다.

## 결정
1. FRONTEND 유지. 서버·실제 LLM·개인정보 처리 없이 fixtures 초기값과 ApiClient의 브라우저 탭 sessionStorage로 가상 신고·공감·읽음을 연결한다. 실제 데이터를 입력하지 않는다.
2. 자동 정보는 고객 여부에, 전달 내용은 최종 확인 펼침에 통합. 기존 step=1→2, step=6→7 호환. B=6단계(0,2,3,4,5,7), A=5단계(0,2,3,4,7). known=off면 첫 단계 제외. A/B 공통 화면은 동일하게 변경.
3. 최종 확인 기본은 짧은 요약, 상세 수정(제목·설명·재현·유형)은 선택. B의 펼침 제목은 호출 이후이므로 AI에 전달한 내용, A는 저장되는 내용. 실제 외부 전송 전 보안 통제는 백엔드에서 구현.
4. 작성 중 X/Escape는 계속 작성/내용 지우고 닫기 확인. 세션 중 새로고침 초안 복원 및 유효 단계 보정. 명시적 case와 자체 검사는 결정적 시연을 위해 복원을 사용하지 않는다.
5. 완료의 내 신고에서 보기로 같은 ID 이동. 가상 구조화는 입력·답변을 보존하고 다른 사례로 대체하지 않는다. 사용법 정정 분기 유지.
6. S3에서도 직접 공감(ADR-015 5항 대체). 동일 신고자/결함은 중복 생성하지 않고 건수·내 신고와 일치시킨다.
7. 내 신고 기본은 제목/현재 단계 한 줄/막대/지금 할 일. 번호·전체 단계·안내 전문은 자세히 보기. 끝난 신고는 접고 item 대상은 펼친다. 관리자 대신 보낸 건 별도 묶음. 받은 알림은 접힌 이력.
8. 알림 항목 선택 시 해당 알림 읽음, 배지는 미확인 건수. 실제 발송 없음.
9. 디자인은 06번 0-3 정보 카드/입력란/선택/진행 표시/안내 상자 행과 --pn-* 토큰 사용. 펼침·확인 행동도 18px·56px. SFA 기존 모양 유지.
10. 사용자의 새 독립 작업 트리 요청으로 기존 개수와 무관하게 ux-user-flow를 추가. 기존 작업 트리·main·PHASE 변경, 푸시·머지는 하지 않는다. S4는 별도 작업 트리에서 진행 중이므로 가져오지 않는다.

## 한계와 검증
브라우저 세션은 실제 DB나 보안 저장소가 아니다. 가상 데이터 시연에만 사용한다. 실제 AI·마스킹·처리 순환의 효과는 별도 검증한다. 기존 ui_check 전 조합, 신규 입력→제출→조회, 공감 중복, 알림 읽음, 대리 접수, 닫기/새로고침, 분기, 1888/1280/1024 폭과 디자인 실측을 검증한다.
