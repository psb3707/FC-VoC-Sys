# ADR-028. 신고자 정보 자동 연결과 접수 환경·발생 환경 진단정보

- 상태: 승인 (결정자: 사용자, 2026-11-21. "로그인 정보·오류 발생 환경 자동 수집 및 IT 진단정보 개선" 지시서의 Phase 1 검토 뒤 대화에서 승인)
- 바꿈: ADR-021(접수 환경 진단값을 고정 가상값으로 보여 줌 → 브라우저가 실제로 알려 주는 범위만 자동 기록), ADR-025 결정 3의 대리 접수 대상(모든 FC → 관리자와 같은 지점 FC, 06번·10번 G9의 "지점 FC" 정의와 맞춤)
- 확장: ADR-026·027(발생 환경 표시에 FC 진술 조건과 출처를 함께), ADR-027 결정 8(신고 패널 ①·③의 내용)
- 유지: 신고 저장본에는 `reporterId`·`submittedById`만 두고 이름·지점명은 저장하지 않는다(조회해서 보임). 자유 입력 원문은 페이지 메모리에만(ADR-021). LLM에는 `MaskedInput`만(08번). 실제 SFA 인증·운영 로그 연계는 백엔드·운영 범위.

## 배경
1. 접수 확인 화면은 누가·어느 지점에서 접수하는지 보여 주지 않는다. 대리 접수 안내 상자만 이름을 보인다. IT 신고 패널도 신고자 이름·지점은 있지만 계정 ID·접수자 역할·접수 시각이 흩어져 있다.
2. 접수 환경 진단값(`fixtures/intake-diagnostics.js`의 `PC · Chrome 120.0`, "사무실 컴퓨터")은 실제 브라우저와 관계없는 고정값인데, 화면은 자동 수집값처럼 보인다.
3. 발생 환경 표시는 시연 진단 이벤트(`diagnostics=mobile`)만 보고, 상담에서 FC가 알려 준 고객 휴대전화의 OS·접속 경로·입력 단계는 다른 카드에 있다. 출처가 섞여 보일 수 있다.
4. 관리자 대리 접수 목록에 다른 지점 FC도 나온다. 관리자의 지점 범위(ADR-025 G9)와 어긋난다.
5. IT가 로그를 추적하려면 무엇이 확인됐고 무엇이 연계 전인지 알아야 한다.

## 결정
1. **로그인 사용자 = 지금 역할 전환으로 고른 가상 사용자(프론트 단계).** 화면의 접수자(`submittedById`)는 그 사용자다. 신고자(`reporterId`)는 본인 또는 대리 접수에서 고른 FC다. 이름·역할·지점명은 `AppUser`·`Branch`에서 ID로 조회해 보이고 저장소에 다시 두지 않는다. 백엔드 단계에서는 접수자를 **서버의 인증 세션**에서 정하고, 요청 본문의 `submittedById`·지점 ID는 믿지 않는다(05번 명세에 적음). 로그인 사용자를 찾지 못하면 신원을 만들지 않고 접수를 막는다.
2. **신원 검증.** 접수·참여 요청은 ① 신고자·접수자가 사용자 목록에 있고 ② 각자의 지점이 지점 목록에 있으며 ③ 대리 접수면 접수자가 관리자이고 신고자가 **같은 지점 FC**일 때만 받는다. 어긋나면 저장하지 않고 "신고자와 지점 정보를 확인하지 못했어요"를 보인다. 관리자 대리 접수 목록은 같은 지점 FC만 보인다.
3. **접수 환경 자동 기록(`diagnostics.submission`).** 접수 시각(시스템 시각)·접수 화면(앱이 아는 화면 코드)·접수 기기 유형(PC/휴대폰/태블릿)·브라우저 종류·주 버전만 기록한다. 기기·브라우저는 브라우저가 알려 주는 값(`navigator.userAgentData`, 없으면 User-Agent에서 종류·주 버전만 골라냄)으로 정하고, 알 수 없으면 비운다(미확인). User-Agent 전체·전체 주소·쿼리·쿠키·토큰·세션값은 저장하지 않는다. 오류 코드·업무 화면 ID는 실제 진단 이벤트가 줄 때만 둔다. ADR-021의 고정 접수 환경값은 쓰지 않는다.
4. **발생 환경은 접수 환경과 따로(`diagnostics.incident` + FC 진술).** 발생 환경은 ① 진단 이벤트가 준 값(프론트 단계에서는 `diagnostics=mobile` 시연 이벤트뿐이라 "시연 진단 이벤트(가상)"로 표시)과 ② FC가 알려 준 값(오류가 난 기기·입력 단계·현상·OS·접속 경로·발생 시각, `USER_REPORTED`)으로만 채운다. 접수 환경의 브라우저·기기를 발생 환경으로 복사하지 않는다. 확인하지 못한 항목은 "미확인"이다.
5. **출처는 세 가지로 보인다.** 자동 확인(시스템·브라우저가 알려 줌) / FC 진술 / 확인 필요(미확인). 시연 이벤트는 자동 확인과 구분해 "시연 진단 이벤트(가상)"로 쓴다.
6. **S2 확인 화면.** 요약 카드 아래에 읽기 전용 카드 **"자동으로 연결된 정보"**(신고자·역할, 소속 지점, 계정, 대리 접수면 접수자, 접수 시각 "접수할 때 자동 기록", 접수 화면, 접수 환경)를 둔다. 수정 칸은 없고 "계정이나 지점이 다르면 접수하지 말고 지점 관리자에게 확인해 주세요"를 적는다. 그 아래 **"오류가 발생한 환경"** 요약(발생 기기·OS·브라우저·입력 단계·현상·접속 경로·발생 시각, 값마다 출처)을 두고, 값 보완은 기존 "AI 문의에서 확인한 내용" 카드와 "오류가 난 환경 보완"에서 한다. 상세 진단은 지금처럼 접힌 영역이다. 새 입력 칸은 없다.
7. **S4 신고 패널.** ① 소제목을 "① 신고자와 발생 환경"으로 바꾸고 맨 위에 **신고자 정보** 카드(신고자 이름·역할·계정 ID·소속 지점, 대리 접수면 접수자 이름·역할·계정 ID, 접수 시각, 접수 화면·접수 환경)와 **오류 발생 정보** 카드(기존 "FC가 알려 준 발생 조건"을 넓혀 업무·증상·발생 단계·발생 기기·OS·브라우저·접속 경로·발생 시각)를 둔다. ③ 담당자 처리 카드에 **로그 추적 단서**(확인된 오류 코드, 화면 코드, 오류 발생 시각, 관련 업무 요청 식별자 "연계 전", 관련 시스템 로그 "연계 전", 추가 확인이 필요한 정보)를 더한다. 가짜 로그 결과는 만들지 않는다. 계정 ID는 결함 대장(영업·IT 역할) 화면에만 보이고, FC는 자기 정보만, 관리자는 지금처럼 지점 범위 안의 이름만 본다.
8. **AI에 넘기지 않는다.** 신고자·접수자·지점·계정·접수 환경은 AI 문의·AI 초안 요청에 넣지 않는다(지금처럼 질문 문장·마스킹 설명만). 검사로 확인한다.
9. **로그 추적 설계는 문서만(P1).** 인증 연계, 내부 추적 ID, 운영 로그 조회 권한, 고객 모바일 웹 진단 이벤트는 `docs/proposals/`에 설계안으로 두고 구현하지 않는다.

## 대안(불채택)
- **신고 저장본에 이름·지점명을 함께 저장:** 사람 정보가 저장소에 중복되고, 이동·개명 때 어긋난다.
- **User-Agent 전체를 저장해 IT가 해석:** 필요 이상의 식별값이 남는다.
- **접수 환경 브라우저를 발생 환경 기본값으로 채움:** 고객 휴대전화 오류를 사무실 PC 브라우저로 잘못 기록한다.
- **"관련 로그" 자리에 시연용 로그 줄을 보임:** 실제 분석이 된 것처럼 보인다.
