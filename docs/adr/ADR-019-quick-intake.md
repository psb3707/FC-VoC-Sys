# ADR-019. 전산 오류 접수를 두 화면으로 줄인다

- 결정일은 2026-11-06이다. 설계사 피드백에 대한 두 화면 접수 및 후속 안내 개선안에 사용자가 작업을 요청했다.
- ADR-018의 AI 문의를 첫 화면에서 열 수 있게 하고, 문의 결과를 새 양식으로 옮긴다. S5의 `known=off`와 기존 숫자 단계 시연 주소는 비교·회귀 검증을 위해 기존 흐름을 사용한다.

## 결정

1. 필수 화면은 [문제 알리기]와 [확인하고 보내기]다. 업무와 한 줄 설명을 먼저 받고, 대표·추가 증상과 상세 설명은 필요한 만큼 붙인다. 같은 업무·증상의 공개 오류만 인라인으로 안내한다. 알려진 오류가 있어도 새 접수로 이어갈 수 있다.
2. 고객 상담 중·청약 진행 불가·오늘 처리 마감은 우선 확인 요청의 근거다. 여러 고객에게 발생은 영향 범위다. 기존 처리 등급과 대표 결함 상태를 자동 확정하지 않는다. 접수·부서 전달·담당자 확인·다음 안내 시각은 각각 근거가 있을 때 표시한다.
3. 고객 범위는 한 고객·여러 고객·아직 모름으로 구분한다. 고객번호는 선택값이다. 접수 환경과 사용자가 알려 준 발생 환경을 나눈다. AI 정리는 확인 화면에서 요청하며, 기다리지 않고 보낼 수 있다. 답변으로 확인하지 않은 내용을 만들어내지 않는다. 차단·마스킹 확인은 송신 전 같은 화면에 둔다.
4. FRONTEND는 탭 안 메모리에서 임시저장, 재시도와 후속 행동을 시연한다. 저장 후 닫기·계속 작성·버리기를 구분한다. 고객번호 원값은 임시저장과 내역에서 제외한다. 새로고침 후 복구, 사용자별 영속 저장, 실제 전달·발송은 백엔드에서 연결한다.
5. 완료 화면에서 접수번호를 복사하고 해당 내역을 연다. 같은 오류 참여는 중복 없이 내역에 남기고 취소할 수 있다. 추가 설명·재발·긴급 사정은 기존 접수에 기록한다. 대표 결함의 상태 변경과 연결은 담당자가 결정한다. 운영 연락처·다음 안내 일정·승인된 고객 안내만 표시한다.
6. 첨부, 최근 고객·실제 SFA 화면에서 고객번호 가져오기, 로그인 전 외부 접수는 현재 PoC 범위 밖이다.

## 화면 요소와 홈 대응

06번 0-3절의 콘텐츠 카드·상태 알약·정의 목록 줄·입력란·접힌 정보·보조/주 버튼을 재사용한다. 폭을 넓히는 선택은 데스크톱 접수 패널에만 적용한다. 오류와 상태는 글자로 표시한다.
