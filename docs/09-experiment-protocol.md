# 09. 비교 검증(실험) 프로토콜

> 이 문서는 실험 전 **동결**한다. 동결 후 변경은 ADR로 기록.

## 1. 목적과 판단 기준
- 질문: B(선택 + 한 줄 + AI 되묻기)가 A(선택 + 한 줄)보다 입력 시간·완결성·재질문 항목 수에서 나은가.
- 사전 기준(제안서 6.1): 시간 B ≤ A, 완결성 B > A, 재질문 항목 수 B < A.
- **B가 낫지 않다면 양식으로 가는 결론도 유효한 결과.** 표본이 작아(6~8명) 유의성 검정은 하지 않고 경향만 본다.

## 2. 참가자
- 6~8명: 관리자 1~3명 + 본사 3~5명. 실명·사번 없이 코드(P01…)만 사용. 시작 화면에서 동의 확인.
- 진행 방식(장소·PC 구성)은 **미결 Q1(11/27까지 결정)**. 설계는 PC 1대·1명씩 진행에서도, 다른 PC 접속에서도 쓸 수 있게 한다.

## 3. 설계
각 참가자가 A·B를 모두 사용(개인 내 비교). 시나리오 세트 2개(S1, S2)를 모드에 교차 배정.
| 칸 | 1차 | 2차 |
|---|---|---|
| C1 | A + S1 | B + S2 |
| C2 | B + S1 | A + S2 |
| C3 | A + S2 | B + S1 |
| C4 | B + S2 | A + S1 |
- 미리 섞은 칸 순서표를 `roleGroup`별로 설정에 두고 등록 순으로 배정. 6명이면 완전 균형이 안 되므로 그대로 보고.
- 세트 안 시나리오 순서는 참가자별 고정 시드로 섞는다(재현 가능).
- 각 모드 시작 전 연습 시나리오 1건(측정 제외).
- 세트당 4건 [G6], 참가자당 약 30분.

## 4. 통제
- 실험 중 **알려진 오류 단계 끔**, 사용법 시나리오 제외(조기 종료로 측정 왜곡 방지).
- 자동 수집 값은 시나리오별 가상 값으로 고정.
- 카드는 판정 항목을 나열하지 않고 FC의 **상황 이야기**로 쓴다. 카드는 계속 보이게 둔다. 무관한 정보도 일부 섞는다.
- 모드는 참가자에게 "방식 1/2"로만 표시.
- 프롬프트·공급자·모델은 실험 기간 고정.

## 5. 측정
| 지표 | 정의 |
|---|---|
| 소요 시간 | "시작" 클릭 ~ 제출 확정, **서버 시각**. 카드 읽는 시간 제외 |
| LLM 대기 시간 | `llmWaitMs` 별도 기록. 1차 지표는 총 시간, 대기 제외 시간은 보조 |
| 필수 항목 충족률 | 정답표 항목 중 충족 수 / 전체 수 |
| 누락 항목 수(= 다시 물어야 할 항목 수) | 정답표 대비 빠진 항목 수 |
| 편의성 | 제출 후 1문항, 5점 척도 |
| 되묻기 수 | B에서 제시된 질문 수 |
- **수기 항목 기준을 1차로 한다.** 정답표 항목 중 자동 수집으로 항상 충족되는 것은 `manual=false`로 표시, 합산 시 차이가 희석되므로 수기 항목(`manual=true`) 충족률·누락 수를 1차, 전체 기준은 보조.
- 충족률과 누락 수는 같은 정보의 양면이므로 함께 표기.

## 6. 판정 (완결성)
자유 입력의 충족 여부는 키워드 일치만으로 믿지 않는다.
1. `blind-scoring.csv` 내보내기: 행 순서 섞음, 모드 표기 제거, 두 모드 모두 **같은 양식으로 정리한 티켓 내용**.
2. 판정자가 정답표 항목별로 0/1 표시(엑셀).
3. 동료가 약 20% 교차 판정 → 일치율 보고 [G7].
4. 같은 형식으로 업로드해 요약 생성.
- **인정 기준:** 사용자 입력과 되묻기 답변에 **근거가 있는 항목만** 충족. B의 AI가 사용자가 말하지 않은 정보를 추측해 채운 것은 불인정.
- 판정 기준은 실험 전 이 문서에 구체화해 고정(항목별 인정/불인정 예시는 10번 문서 정답표에).

## 7. 장애·무효 처리
- LLM 실패·규칙 대체 시행은 `llmOutcome`으로 표시. 진행자가 무효 처리 가능(사유 기록).
- 분석은 전체와 정상 시행을 함께 본다.
- 하루 시작 전 LLM 상태 확인, 하루 2~3명, 매일 CSV·DB 백업, 예비일 1일.

## 8. CSV 형식
**`raw.csv`** (시행 1행)
```
participant,role_group,cell,period,seq,mode,set,scenario_id,pair_no,started_at,submitted_at,
duration_ms,llm_wait_ms,net_duration_ms,followup_count,usability_1to5,
key_total,key_met,key_missing,manual_total,manual_met,manual_missing,
llm_provider,llm_model,prompt_version,llm_outcome,status,invalid_reason
```
**`blind-scoring.csv`:** `blind_id, scenario_id, ticket_text, item_code, item_label, is_manual, score_0_1, scorer`
**`summary.csv`:** 모드별 n, 시간 중앙값·범위, 수기 항목 누락 중앙값, 전체 충족률, 편의성 중앙값 + 참가자별 B−A 차이 + 순서별·세트별 분해.
- UTF-8 BOM(엑셀 한글 깨짐 방지). 통계는 중앙값, 참가자별 쌍 차이, "몇 명 중 몇 명 개선" 중심.

## 9. 결과 보고 시 한계 명시
작은 표본, 본인 판정(교차 20%), 가상 시나리오, 단일 모델·프롬프트, 학습 효과 통제의 불완전성(6명 칸 불균형).
