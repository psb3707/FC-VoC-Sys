# 08. 개인정보 보호·보안 설계서

원칙: **AI에게는 "누구"가 아니라 "어떤 상태"를 넘긴다.** AI로 마스킹하지 않고 규칙으로 한다.

## 1. 처리 규칙 (`config/privacy-patterns.yml`)
| 순서 | 대상 | 처리 | 방식 |
|---|---|---|---|
| 0 | 업무 번호 후보 표시 | 2·3번 예외용 | 문맥·사전으로 번호 위치를 먼저 찾아 둠 |
| 1 | 주민등록번호 | **차단** | 6+7자리, 하이픈·공백·전각 변형 포함 |
| 2 | 카드번호 | **차단** | 16자리 묶음(Luhn 불일치도 차단) |
| 3 | 계좌번호 | **차단** | 10~14자리 숫자·하이픈. 업무 번호(4번)는 제외. 문맥 없는 긴 숫자는 계좌로 보아 차단 [G3] |
| 4 | 증권·계약·설계·고객번호 | **참조키** `K-01` | 가상 사전 + "증권번호 ○○" 문맥. 2·3번보다 먼저 판별 |
| 5 | 전화번호 | `[전화]` | 휴대폰·지역번호, 구분자 변형 |
| 6 | 주소 | `[주소]` | 시·도·구 이후 상세, 도로명 |
| 7 | 이름 | `[고객]` | 시드 이름 사전 + 호칭 문맥(○○○ 고객님, 계약자 ○○○) + 라벨 문맥 |
- 입력 정규화(NFKC, 공백·하이픈 변형 통일) 선행.
- 차단 시: LLM 호출 0회, DB·파일·애플리케이션 로그에 값 저장 0건. **탐지 유형만 기록**.

## 2. 이름 마스킹의 한계 (명시)
규칙만으로 임의의 한국어 이름을 완벽히 찾을 수 없다. 문맥 없는 이름 단독 입력은 놓칠 수 있다. 세 겹으로 보완한다.
1. 불확실하면 과잉 마스킹.
2. 사용자 전송 전 미리보기 확인(마스킹 발생 시 자동 펼침).
3. 입력란 근처 "이름·번호를 적지 마세요" 안내.
"누락 0건"은 **테스트 말뭉치 기준 결과**로 설명한다.

## 3. 참조키
- 고객번호 별도 입력란 값은 파이프라인을 우회해 바로 참조키로 변환. 프롬프트에 원값이 들어가지 않는다.
- 참조키는 신고별로 K-01부터 새로 시작 → AI 로그 간 연결 방지.
- `RefKeyMap` 원값은 서버 로컬 DB에만 두고 API로 노출하지 않는다.

## 4. 속성 전달
참조키로 가상 계약 조회 → 범주형 속성만. **허용 목록(allow-list)** 으로 고정해 새 필드가 자동 전달되지 않게 한다.
| 속성 | 일반화 |
|---|---|
| 계약 상태 | 범주(유지/실효/해지 등) |
| 상품군 | 상품군 단위(종신, 정기 등) |
| 최근 변경 유형·월 | 유형 + 연-월 |
| 청약 경로 | 범주(대면/모바일 등) |
예: `{"ref":"K-01","contractStatus":"유지","productGroup":"종신","lastChange":{"type":"계약자변경","month":"2026-11"},"channel":"모바일"}`
희귀 속성 조합에 의한 재식별 위험은 가상 데이터라 PoC에서는 수용하고, 운영 전환 시 과제로 남긴다.

## 5. 유출 방지 지점
- **모든 사용자 입력**(한 줄, 되묻기 답변, 안내문 초안용 결함 설명 포함)이 파이프라인을 거친다.
- `OutboundGuard`: 송신 직전 재검사. 탐지 시 송신 거부.
- 요청 본문을 애플리케이션 로그에 남기지 않는다. 예외 메시지에 입력값을 넣지 않는다.
- 화면 이미지는 AI로 보내지 않는다.

## 6. 실제 SFA 저장본(`references/`) 취급
- 로그인 상태에서 저장한 실제 페이지. 실존 인물로 보이는 호칭 표현과 긴 숫자가 포함돼 있다(값은 열람 대상 아님).
- **배치·메뉴 이름·스타일 참고용**. 앱에 포함하지 않고, Git에 올리지 않는다. Claude 훅이 쓰기를 막는다.
- Claude(외부 LLM)는 원본을 직접 읽지 않고 `scripts/ref_outline.py`의 **마스킹된 구조 요약만** 본다. 출력은 화면에 띄우기 전 자동 검사(성씨 3글자 잔여·데이터 행·회사명)를 통과해야 하고, 임시 출력은 확인 후 지운다(ADR-011, 사고 기록 포함).
- 목업(S1)은 실제 화면을 HTML/CSS로 충실히 재현하고, 이름·숫자·일정·표·공지 제목은 전부 가상 데이터로 채운다. 회사명·서비스명·로고·상품 브랜드는 쓰지 않는다(ADR-012). 실제 화면 캡처는 앱·저장소에 넣지 않는다.
- **실제 화면 스크린샷**(사용자가 준 기준 화면): 저장소 밖에만 보관. Claude는 원본을 Read 등으로 직접 열지 않고 `scripts/ref_blur.py`의 **흐림 6px 이상 사본**만 본다(6 미만 거부, 확대는 흐림 뒤). 사본·비교 결과는 `target/`(Git 제외)에만 두고, `scripts/ui_compare.py`도 원본을 흐림 없이 출력·저장하지 않는다. 외부 공개 자료에는 넣지 않는다.
- 시드·평가 데이터에 이 파일의 값을 복사하지 않는다(수작업 체크리스트, 저장본이 Git에 없어 자동 테스트가 참조 불가).

## 7. 시크릿
API 키는 환경 변수만. `.gitignore`에 `.env*`, pre-commit이 키 형식 문자열 커밋을 거부. 문서·로그·fixtures에 키 금지.

## 8. 사내 기준 확인
마스킹·참조키 방식이 사내 기준에 충분한지는 11/13까지 정보보호·준법에 확인한다 [Q3]. **테스트 통과가 사내 기준 충족을 뜻하지 않는다.**

## 9. 테스트 요약 (상세: 11번)
개발 말뭉치 30건+ 누락 0, 보류 말뭉치 10건+(동료 작성) 누락 0, 과잉 마스킹 15건, 차단 시 LLM 호출 0회, 전체 경로 감사(로그에서 시드 개인정보 0건), `MaskedInput` 타입 경계.
