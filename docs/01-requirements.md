# 01. 요구사항 명세서

> 상태: 초안 v0.1. 원천: 요청 프롬프트 3~9절, `proposal.md` 4·7장.

## 1. 목적과 핵심 질문
1. **(핵심)** 같은 시나리오에서 "선택 + 한 줄 + AI 되묻기(B)"가 "선택 + 한 줄(A)"보다 입력 시간, 필수 재현 정보 완결성, 다시 물어야 할 항목 수에서 나은가?
2. 접수부터 경과 공유까지의 순환을 현장 사용자가 이해할 수 있게 시연할 수 있는가?
3. 고객 정보를 AI에 보내지 않고도 AI가 분류·안내를 할 수 있는가?

판단 기준(실험 전 고정): 시간은 B가 A와 같거나 짧음, 완결성은 B가 A보다 높음, 재질문 항목 수는 B가 A보다 적음. **B가 낫지 않다면 양식으로 가는 결론도 유효한 결과**(제안서 4.4).

## 2. 범위
| 구분 | 내용 |
|---|---|
| Must | 접수 패널, A모드, 비교 검증 모드, 마스킹 모듈과 테스트, 결함 대장 최소판(M\*) |
| Should | 대장 확장(필터·안내문 승인 등), "알려진 오류·내 신고" 탭, FC용 안내문 미리보기, 대장의 새 신고 알림과 AI 비슷한 결함 추천(ADR-017), 접수 채널 AI 문의(ADR-018), 역할별 알림·두 갈래 진행 표시·업무 재개 회신·관리자 지점 FC 문의(ADR-025), AI 문의 되묻기·접수 인계와 새 신고 규칙 후보(ADR-026), 빠른 도움·간편 알리기·FC별 현황(ADR-027), 신고자 정보 자동 연결·접수/발생 환경 진단(ADR-028), 알림 요약·수정 검증 기록·FC 현장 확인(ADR-029), 업무 분류·담당 문의함·인수·현업 초기 대응·IT 사전 협의·ITGS 요청 초안(ADR-030) |
| Could | 사용 현황 간단 통계 |
| 제외 | 실제 SFA 수정·연동, 실제 알림톡·메신저 발송, 그룹웨어·업무 메신저 알림, ITGS 연동(요청·결재·배정), 전화 녹취·자동 통화, 실제 로그 연동, 화면 캡처 첨부·이미지 처리, AI가 사람 확인 없이 신고를 결함에 자동 연결(후보 추천은 REQ-LG-06, ADR-017), SLA 자동화, 로그인·권한(역할 전환 상자로 대체), 운영 배포 |

## 3. 사용자
FC(고령 포함), 지점 관리자(대리 접수), 현업 담당자(업무 담당 부서의 문의 대응·임시조치, 역할 코드 `SALES`, ADR-030), IT(사전 협의·수정·보류 결정). 모두 가상 사용자.
