# 06. 화면 정의서

> 프론트 단계의 구현 기준이자 M2(화면 완료) 완료 기준. 와이어프레임은 11/13까지 이 문서에 첨부(이미지 또는 ASCII)한다.
> 참고 배치(제안서 2.4): 상단 업무 메뉴·유틸리티(제보, 원격지원 등), 왼쪽 사용자·실적 카드, 가운데 일정·탭·공지 탭, 오른쪽 큰 버튼 퀵메뉴(챗봇·원격요청 포함).

## 1. 공통 기준
| 항목 | 기준 |
|---|---|
| 글씨 | 본문 18px 이상, 제목 24px 이상. 시스템 글꼴(맑은 고딕) |
| 버튼 | 주요 버튼 높이 56px 이상, 간격 충분, 한 화면 한 가지 주 행동 |
| 대비 | 4.5:1 이상. 색에만 의존하지 않고 글자·아이콘 병기 |
| 문구 | 쉬운 말. 예) "재현" → "다시 해봐도 같은 문제가 나는지" |
| 프론트 단계 표시 | 상단에 "화면 시안 – 실제 동작 안 함" |
| 데이터 | `js/fixtures/` 고정값, 통신은 `js/api-client.js` 한 곳 |
| 실행 | HTML 더블클릭으로 열림(서버·Node 불필요) |

| ID | 화면 | 파일 | 대상 | 우선 |
|---|---|---|---|---|
| S1 | SFA 메인 목업 | `index.html` | FC·관리자 | M |
| S2 | 접수 패널 (오른쪽에서 열림) | `index.html` 내 | FC·관리자 | M |

## 3. S1 SFA 메인 목업
- 배경: `assets/sfa-main-masked.png` (개인·실적·회사 식별 정보를 가린 캡처). 원본 SFA HTML은 쓰지 않음.
- 오른쪽 퀵메뉴(챗봇·원격요청 근처)에 큰 버튼 **"전산 오류 접수"**. 상단 "제보"(보험사기 신고)는 건드리지 않음.
- 가운데 공지 탭 줄(일반공지, 시스템공지, CEO 메시지, 영업자료실) 끝에 **"알려진 오류·내 신고"**.
- 위치는 화면 비율 기준 좌표로 지정(해상도 달라져도 어긋나지 않게).
- 역할 전환 상자(FC / 관리자 / 영업팀 / IT)와 사용자 선택.
- 캡처가 없는 동안(11/13 전)은 회색 레이아웃 블록으로 대체.

## 4. S2 접수 패널
오른쪽에서 열리는 패널. 단계 표시줄을 위에 둔다.
| 단계 | 내용 | 비고 |
|---|---|---|
| 0 | 알려진 오류 카드(같은 화면·증상). "나도 겪었어요" / "다른 문제예요" | 실험 모드에서는 이 단계를 끔 |
| 1 | 자동 수집 정보: 화면, 기기·브라우저, 시각 ("묻지 않아도 붙는 정보") | |
| 2 | "고객 관련 오류인가요?" 예/아니요. 예이면 고객번호 별도 입력란("AI에는 보내지 않아요") | |
| 3 | 업무(로그인, 청약·서명, 고객조회, 가입설계 등) 큰 버튼, 증상 유형 큰 버튼 | |
| 4 | 한 줄 입력("이름·번호는 적지 마세요" 안내) | 차단 경고(주민/계좌/카드) 표시 |
| 5 | (B) AI 되묻기 카드 최대 3개, 선택지 또는 짧은 입력 | A모드는 건너뜀 |
| 6 | "AI에게 전달되는 내용" 미리보기. 마스킹 발생 시 자동 펼침 | A모드는 저장용 마스킹 결과만 |
| 7 | 접수 결과: 구조화 티켓, 유형, 처리 등급, 담당 부서. 사람이 확인·수정 후 제출 | 사용법이면 안내 후 종료 |
| 대리 | 관리자일 때 "누구의 신고인지" 선택 | 상단 |
**분기 화면(모두 만든다):** 알려진 오류로 종료, 사용법 안내로 종료, 입력 차단 경고, LLM 지연(로딩), LLM 실패→규칙 되묻기, 고객 관련 경로, 대리 접수.
**A/B 차이:** `mode` 값 하나로 5·6단계의 AI 부분만 켜고 끈다.

## 5. S3 알려진 오류·내 신고
- 알려진 오류 목록: 제목, 임시 우회법, 수정 예정일, 신고 건수.
- 내 신고: 단계 진행 표시(접수→…→해결/수정하지 않음), 승인된 FC용 안내문.
- 알림 미리보기 내역.

## 6. S4 결함 대장
- 목록: 유형, ID, 신·구, 영향 지점 수, 신고 수, 등급, 상태, 부서. 기본 정렬 영향 지점 수 × 업무 중요도. 필터.
- 상세: 연결된 신고 목록, 상태 이력, 우회법·예정일.
- 신고 연결(미연결 신고 목록에서 선택).
- 상태 변경 대화상자: 다음 상태 선택, 예정일/사유 입력 → **"묶인 신고자 N명에게 알림" 미리보기** → 확정.
- 안내문: AI 초안 생성 → 수정 → 담당자 승인(S).

## 7. S5 참가자 실험
- 왼쪽 고정 시나리오 카드, 오른쪽 S2 패널 재사용(알려진 오류 단계 끔).
- 모드는 숨기고 "방식 1 / 방식 2"로 표기. 시작 버튼, 제출 후 편의성 5점(큰 버튼), 완료 안내.
- 시작 화면: 참가자 코드, 동의 확인.

## 8. S6 진행자
- 참가자 등록·칸 배정 확인, 진행 현황, LLM 상태(공급자·모드·성공률), 시행 무효 처리, CSV 내보내기, 판정 업로드, 요약표.

## 9. 화면 흐름
```
S1 ─ 접수 버튼 → S2 ─ 알려진 오류 → "나도 겪었어요" → 종료
                      ├ 사용법 → 안내 → 종료
                      └ 결함·개선 → 티켓 → S4(대표 결함 연결·상태 변경) → 알림 미리보기 → S3(FC 확인)
S6 → S5 (반복) → S6
```
