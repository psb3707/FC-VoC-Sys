# 06. 화면 정의서

> 프론트 단계의 구현 기준이자 M2(화면 완료) 완료 기준. 와이어프레임은 11/13까지 이 문서에 첨부(이미지 또는 ASCII)한다.
> 참고 배치(제안서 2.4): 상단 업무 메뉴·유틸리티(제보, 원격지원 등), 왼쪽 사용자·실적 카드, 가운데 일정·탭·공지 탭, 오른쪽 큰 버튼 퀵메뉴(챗봇·원격요청 포함).

## 0. 디자인 원칙 (ADR-011, ADR-014, ADR-016)
1. **기존 화면은 그대로, 추가는 세 가지만.** 퀵메뉴 버튼 "전산 오류 접수", 공지 탭 "알려진 오류·내 신고", 기존 알림 아이콘의 숫자 배지.
2. **진입점은 기존 SFA 모양을 그대로** 따른다(0-1 토큰). 원래 있던 기능처럼 보여야 한다. 아이콘만 두지 않고 글자를 붙인다.
3. **열리는 패널과 결함 대장은 새 접근성 기준**(1절)을 따른다. 기존 12~14px 화면과의 대비 자체가 개선점으로 보이게 한다. 결함 대장(SFA 밖)은 SFA 모양을 흉내 내지 않는다.
4. **순환이 보이게.** 핵심 장면은 "결함 대장에서 상태 변경 → SFA 화면의 기존 알림에 배지 → 내 신고에서 경과 확인"이다.
5. **전·후 비교는 발표 구성으로.** 프로토타입에 비교 화면을 넣지 않는다(현재 흐름 장표 1장 → 사례 ① 목업 시연).
6. **실제 SFA를 HTML로 충실 재현, 실데이터 자리는 가상 데이터**(ADR-012). 사용자가 준 기준 스크린샷(1888×952, 저장소 밖)과 배치·비율·색·모서리·그림자를 맞추고, 이름·숫자·일정·표·공지 제목은 `js/fixtures/` 가상 값으로 채운다. 로고·캐릭터는 실제 이미지(`img/logo.png`, `img/mascot.png`)를 쓴다(ADR-013·016, 저장소 외부 공개 시 `static/img/` 제외). 로고 이미지 밖의 HTML 글자로는 회사명·서비스명과 상품 브랜드를 쓰지 않는다(가상 상품명, CSS로 그린 중립 배너). 화면 안에 "시안" 표시를 두지 않고, 실제 동작이 없다는 점은 발표·시연 때 구두로 알린다(ADR-016). 재현도는 `scripts/ui_compare.py`로 확인한다(11절).
7. 시연용 강조(진입점 외곽선 깜빡임 등)는 선택 기능으로 두고 **기본 끔**.

### 0-3. 홈 디자인 대응표 (ADR-014)
새 화면의 요소는 아래 행 중 하나를 따른다. 크기(글자 18px·버튼 56px)와 강조색(`#0077b3`)은 0-2절이 우선이고, **모양(모서리·그림자·테두리 유무·색 계열·글자 간격)은 홈을 따른다.** 표에 없는 모양이 필요하면 먼저 행을 추가한다. 홈 값은 2026-11-03 Playwright 실측(1888×952), 패널 값은 S2(`css/panel.css`) 적용값.

### 4-1. 접수 채널 AI 문의 (ADR-018)

- S2 0단계 상단에 퀵메뉴 모양의 [AI에게 물어보기]를 둔다. 기존 패널 안에서 열며 일반 접수 단계 표시줄은 접는다.
- 첫 화면에 추천 질문과 질문 범위를 표시한다. 추천 질문은 0-3절의 알약 모양과 보조 버튼 규격을 따르고, 결과는 콘텐츠 카드·상태 태그·정의 목록 줄을 따른다. 질문란과 보내기 버튼은 패널 아래에 둔다. 본문이 길어지면 본문만 스크롤한다.
- 결과에 문의 유형, 공개 유사 사례의 대장 번호·처리 상태·임시 방법·예정일(있을 때)을 표시한다. 공개 유사 사례가 없거나 조회가 실패해도 질문을 접수 양식으로 옮길 수 있다.
- 직접 열기 주소는 `index.html#role=FC&panel=intake&step=assistant`다. `llm=fail`은 조회 실패를 시연한다. 질문과 답변은 페이지 내에서만 유지한다. `mode=A` 또는 `known=off`에서는 일반 접수로 연다.

AI 문의의 첫 제목·설명·추천 질문은 약 50ms 간격으로 나타난다. 보내면 점 세 개와 처리 상태를 표시하고, 가상 응답을 받은 뒤 브라우저에서 답변을 순차적으로 표시한다(ADR-020). 스크린리더는 시작과 완료 상태를 듣고 완성된 답변을 읽는다.

### 4-2. 두 화면 접수 (ADR-019)

- 일반 진입은 `step=problem`에서 업무와 한 줄 설명을 먼저 받는다. 긴급 사정과 추가 증상·설명은 펼쳐서 입력한다. 입력과 맞는 공개 임시 방법이 한 건이면 한 줄 설명 바로 아래에 안내하고, 자세한 방법과 참여는 펼쳐서 보여 준다. [해봤는데 아직 안 돼요]는 시도한 방법을 확인 화면으로 넘긴다. 일치하는 방법이 없으면 같은 업무의 공개 오류를 접어서 제공한다. `step=review`는 접수 요약을 먼저 보여 주고 고객 범위, 접수/발생 환경, 연락 희망, 개인정보와 선택적 AI 정리는 아래에서 펼칠 수 있다.
- 일반 접수와 AI 문의는 패널 오른쪽 위의 [AI 모드]와 [일반 접수]로 오간다. 전환 전 작성 내용과 확인 단계는 유지한다. 새 AI 문의를 열 때 한 줄 설명을 질문란에 옮기고 보내기는 사용자가 누른다. 상단 전환 버튼은 0-3절 보조 버튼 토큰을 쓴다.
- AI 문의에서 [이 내용으로 문의 접수]를 누르면 같은 첫 화면에 옮긴다. 접수 미완료 시 탭 내 임시저장과 재시도를 지원한다. 완료 화면은 `step=receipt`이며 접수번호 복사와 해당 내역 보기가 있다. 초록색 체크가 등장해 선이 그려지고, 완료 문구와 버튼은 바로 보인다(ADR-020).
- 숫자 단계 및 `known=off` 실험 경로는 기존 흐름을 사용한다. 첫 제출만 실패하는 시연은 `submit=fail`, AI 대기/실패는 `llm=slow|fail`이다.
- [오류 현황]과 [내 접수내역]에서 공개 안내와 내 접수 기록을 각각 보여 준다. 후속 기록은 기존 접수에 붙으며, 참여 취소·추가 설명·재발·긴급 사정을 같은 내역에서 처리한다.

### 4-3. 진단정보와 해결 안내 (ADR-021)

- 확인 화면의 [첨부되는 진단정보 보기]에 접수 환경과 발생 환경을 분리한다. 시연 주소의 `diagnostics=mobile`은 고객 휴대폰 발생, `diagnostics=fail`은 발생 진단 수집 실패다. 확인되지 않은 항목은 미확인으로 표시하고 직접 보완할 수 있다.
- 담당자가 대장에서 새 접수를 결함에 연결한 뒤 해결로 변경할 때 적용 시각과 범위, 변경 내용, 기존 건 처리 방법을 확인한다. 공개 안내를 승인하면 수신자별 새 알림을 만든다. `notify=fail`에서 실패 이력과 재시도를 확인할 수 있다.
- SFA 알림은 읽기 전 배지로 표시한다. 항목을 열면 해당 접수로 이동하고, 내역에서 적용 시점과 재시도·재발송 여부를 본다. 재발은 같은 접수의 이력이다.

### 4-4. 화면 첨부와 AI 접수 초안 (ADR-022)

- 일반·AI 접수 확인 화면에서 화면 이미지 한 장을 선택하고, 자르기·가림·최종 확인 후 첨부한다. `attachment=fail`은 첫 첨부 실패 시연이다. 삭제한 뒤 글만으로 접수할 수 있다. 결함 대장은 연결 전과 연결 후에 확정본을 열어 볼 수 있다.
- AI 문의의 [AI와 접수 초안 만들기]는 `step=ai-draft`를 연다. 가려진 입력을 확인하고 선택 질문에 답하거나 건너뛴 뒤 초안을 수정한다. 고객이 말했다는 내용은 직접 확인한 사실이나 완료 여부로 확정하지 않는다.

## 5. S3 알려진 오류·내 신고
배치(ADR-015): **공지 카드 안 요약 + 오른쪽 패널.**
- **공지 카드 요약**(진입점, 기존 모양 `data-a11y="sfa"`): 5번째 공지 탭을 누르면 공지 목록 자리에 공지 목록 줄(0-1)과 같은 모양으로 `[내 신고] 제목` · 지금 상태, `[알려진 오류] 제목` · 수정 예정일(또는 "수정하지 않음")을 4줄까지(내 신고 최신 2건 + 알려진 오류 2건). 줄을 누르면 패널이 그 항목의 탭으로 열린다.
- **패널**(새 요소, S2와 같은 틀: 폭 520px·1280 미만 100%, 머리 아이콘 원 + 제목 "알려진 오류·내 신고" + 닫기). 머리 아래에 전환 탭 [알려진 오류] [내 신고](높이 56px, 선택 탭은 흰 바탕·굵게).
  - 알려진 오류 목록: 제목, 지금 상태(글자), 임시 우회법, 수정 예정일 또는 고치지 않는 이유, 같은 신고 건수. "나도 겪었어요"는 S2 0단계에만 있고 여기서는 안내 문구로만 알린다.
  - 내 신고: 단계 진행 표시(접수 → 문제 확인(02번 "재현 확인") → 원인 파악 → 임시조치 → 수정 예정 → 해결 / 수정하지 않음). 지금 단계는 글자("6단계 중 4단계 · 임시조치")와 단계 이름 줄로 알리고, 막대는 장식이다. 승인된 FC용 안내문만 보이고(REQ-NT-01), 없으면 "담당자 안내는 아직 없어요". 수정하지 않음이 되면 막대는 직전 단계까지만 채우고 "수정하지 않음 · ○○ 단계에서 끝났어요"로 알린다.
  - 알림 미리보기 내역: [내 신고] 탭 아래 "받은 알림"(시각, 알림 문구).
  - 빈 화면: 신고가 없으면 "아직 보낸 신고가 없어요"와 접수 방법 안내.
- 데이터: `ApiClient.getKnownErrors()`, `getMyReports(userId)`, `getNotifications(userId)` (05번 3절, 상태 코드·응답 형식은 05번 1절·4절).

## 6. S4 결함 대장
- 목록: 유형, ID, 신·구, 영향 지점 수, 신고 수, 등급, 상태, 부서 + 경과·최근 신고·**확인할 것**(02번 5-2절). 판단에 덜 쓰는 값(유형·신·구·부서)은 열이 아니라 결함 칸 안 태그·작은 줄로 합친다. 기본 정렬 영향 지점 수 × 업무 중요도. 필터.
- 상세: 확인할 것, 원인과 상태 이력, 연결된 신고 목록, 우회법·예정일. 보는 역할에 따라 순서를 바꾼다(영업팀은 안내문을, IT 담당은 원인·이력을 위로).
- 신고 연결(미연결 신고 목록에서 선택).
- 상태 변경 대화상자: 다음 상태 선택, 예정일/사유 입력 → **"묶인 신고자 N명에게 알림" 미리보기** → 확정.
- 안내문: AI 초안 생성 → 수정 → 담당자 승인(S).
- 새 신고 알림(REQ-LG-07, S): 머리 "새 신고" 버튼 배지·목록, 탭 "새 N" 배지, 줄 "새로 들어옴" 태그(ADR-017).
- AI 비슷한 결함 추천(REQ-LG-06, S): 안 묶인 신고마다 후보 1~3개·이유·비슷함 정도. 연결은 담당자(ADR-017).
- 글자 찾기(REQ-LG-08, S): 필터 줄의 찾기 입력란. 낱말이 들어간 건만 보이고 필터와 함께 적용한다. AI를 쓰지 않는다.

| 신고 묶기 대화상자(가운데) | 제목 "어느 대표 결함에 묶을까요?" → 소제목 **"묶을 신고"** + 신고 카드 → (AI 추천이 있으면) 소제목 **"AI가 비슷하다고 본 결함 N건"** + "AI 추천 · 담당자가 확인해요" + 후보 선택 버튼(제목 / ID·지금 상태·비슷함 / 이유) → 소제목 **"다른 대표 결함 M건"**(추천이 없으면 "대표 결함 N건 중 고르기") + 나머지 선택 버튼. 후보 없음·지연·실패는 목록 위 안내 상자(실패는 경고 상자)로 알리고 목록은 그대로 고를 수 있다. 덩어리 사이는 소제목 또는 16px로 띄운다(카드끼리 붙지 않음, 자체 검사 `s4-block-gap`). [묶기] → 끝 |
| 안내문 | 상세 패널 카드에서 승인본·초안·없음을 보여 준다. AI 초안 만들기·수정·승인 동작은 아직 없다(S) |

**요소 표시.** 검사 대상은 HTML 속성으로 구분한다.
- `data-a11y="new"`: 새 요소(안내 상자, 패널, 배지·팝업 내용). 글자 18px 이상, 클릭 요소 높이 56px 이상.
- `data-a11y="sfa"`: 기존 SFA 모양(진입점 포함). 0-1 토큰과 일치(퀵메뉴 96px·모서리 16px·글자 14px, 공지 탭 높이 44px·모서리 12px·글자 14px·폭 60px 이상, 5개가 탭 줄 안 한 줄).
- `data-clip-ok`: 원래 화면처럼 일부러 잘라 보이는 영역(날짜 카드 슬라이더). 글자 잘림 검사 제외.
- `data-a11y="replica"`: 실제 SFA를 재현한 기존 요소와 그 안의 가상 데이터(ADR-012). 원본 모양 유지가 우선이므로 글자 크기·대비 검사 제외(진입점은 `sfa`로 따로 검사).
- `data-a11y="badge"`: 알림 배지. 0-2 값(배경 `#d93025`, 흰 글자, 최소 18px)과 대비만 검사(기존 아이콘 위 작은 숫자라 18px 글자 기준 제외).

**자체 검사.** `index.html?selftest=1#<상태>`(S4는 `ledger.html?selftest=1#<상태>`) 로 열면 `js/dev/selftest.js` 가 실행되어 `<pre id="selftest-result">` 에 `{ok, checks:[{name, pass, detail}]}` 를 남긴다. 항목: 새 요소 크기, SFA 토큰 일치, 대비(4.5:1, 큰 글자 3:1, replica 제외), 가로 넘침·글자 잘림 0건, 보이는 글자·탭 제목에 "시안" 없음(ADR-016), 패널 맨 아래가 행동 줄(S2)·본문(S3). S4(`<body data-screen="ledger">`)는 SFA 홈 전용 항목(퀵메뉴·공지 탭·진입점)을 건너뛰고, 페이지 제목 24px, 탭 2개·선택 하나 굵게, 표 행 56px 이상·세로 칸 선 없음, 카드 테두리+그림자 겹침 없음·모서리 24px, "총 N건", 상세 패널 틀(오른쪽 520px·행동 줄 맨 아래·주 버튼 하나), 대화상자(화면 안 가운데·모서리 24px·단계 글자·주 버튼 하나 56px `#0077b3`), 패널·대화상자 본문 덩어리가 겹치거나 카드끼리 12px 미만으로 붙지 않음(`s4-block-gap`), 새 신고 배지(0-2 값)와 팝업(0-1 값), AI 추천에 "AI 추천" 표시와 비슷함 글자가 있음(`s4-ai`)을 본다. 평소 열 때는 실행되지 않는다.

**디자인 일관성 검증(ADR-014).** 자동 검사는 접근성 하한만 본다. 홈과 같은 시각 언어인지는 아래 두 단계로 확인한다.
1. **착수 전 – 대응표.** 새 화면에 쓸 요소를 나열하고 각각 0-3절의 어느 행을 따르는지 PR 본문 "디자인 대응표"에 적는다. 표에 없는 모양은 0-3절에 행부터 추가한다.
2. **완료 후 – 실측 비교.** 자동 검사 통과 뒤 디자인 일관성 리뷰어(`.claude/agents/design-consistency-reviewer.md`)를 서브에이전트로 돌린다. 리뷰어는 읽기 전용으로, 로컬 서버(`python -m http.server`, Playwright는 `file://`을 막음)로 연 화면에서 홈과 새 화면의 계산 스타일(글꼴·글자 간격·모서리·그림자·테두리·색)을 실측해 0-3절과 비교하고, ① 어긋남(실측값·제안 CSS) ② 시각 버그 ③ 잘 맞는 점(건드리지 말 것)을 보고한다. 지적 사항을 같은 PR에서 고치고 `ui_check.py`를 다시 돌린다. 심각하지 않은 동작 버그는 별도 `fix/` 브랜치로 뺀다.
- S4~S6(SFA 밖)은 홈 대신 S2 패널을 기준으로 비교한다(ADR-014 결정 5).
- 리뷰어 캡처는 `target/` 아래에만 저장하고, 끝나면 로컬 서버를 끄고 `.playwright-mcp/` 기록을 지운다.

**실제 SFA 재현도 비교(ADR-012).** 기준 스크린샷은 저장소 밖에 두고, 원본을 직접 열지 않는다.
```
python scripts/ref_blur.py "<스크린샷>" [--blur 6] [--crop x,y,w,h] [--zoom 2] [--out 경로]
python scripts/ui_compare.py "<스크린샷>" [--blur 6] [--offset-y N]
```
- `ref_blur.py`: 흐림 사본을 만든다(기본 `target/ref-blur/`). blur 6 미만은 거부. 확대는 흐림 **뒤**에 해서 글자가 읽히지 않는다. Claude는 이 사본만 본다.
- `ui_compare.py`: `index.html?compare=1` 을 원본 크기로 headless Chrome 캡처하고, 두 이미지에 같은 흐림을 적용해 전체 유사도(%)와 8×6 격자별 유사도를 표로 출력한다. `target/ui-compare/` 에 흐림 원본·흐림 재현을 **반반 겹친 PNG**(`overlay.png`)와 **나란히 놓은 PNG**(`side.png`)를 저장한다. 원본을 흐림 없이 출력·저장하지 않는다. `--offset-y` 는 스크린샷 맨 위가 잘린 만큼 우리 캡처를 위로 당긴다.
- 숫자보다 겹친 이미지에서 상자 위치·크기·색이 맞는지를 우선 본다. 가상 데이터 글자 차이는 허용.
