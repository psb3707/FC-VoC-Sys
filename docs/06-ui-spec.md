# 06. 화면 정의서

> 프론트 단계의 구현 기준이자 M2(화면 완료) 완료 기준. 와이어프레임은 11/13까지 이 문서에 첨부(이미지 또는 ASCII)한다.
> 참고 배치(제안서 2.4): 상단 업무 메뉴·유틸리티(제보, 원격지원 등), 왼쪽 사용자·실적 카드, 가운데 일정·탭·공지 탭, 오른쪽 큰 버튼 퀵메뉴(챗봇·원격요청 포함).

## 0. 디자인 원칙 (ADR-011, ADR-014, ADR-016)
1. **기존 화면은 그대로, 추가는 세 가지만.** 퀵메뉴 버튼 "전산 오류 접수", 공지 탭 "알려진 오류·내 신고", 기존 알림 아이콘의 숫자 배지.
2. **진입점은 기존 SFA 모양을 그대로** 따른다(0-1 토큰). 원래 있던 기능처럼 보여야 한다. 아이콘만 두지 않고 글자를 붙인다.
3. **열리는 패널과 결함 대장은 새 접근성 기준**(1절)을 따른다. 기존 12~14px 화면과의 대비 자체가 개선점으로 보이게 한다. 결함 대장(SFA 밖)은 SFA 모양을 흉내 내지 않는다.
4. **순환이 보이게.** 핵심 장면은 "결함 대장에서 상태 변경 → SFA 화면의 기존 알림에 배지 → 내 신고에서 경과 확인"이다.
5. **전·후 비교는 발표 구성으로.** 프로토타입에 비교 화면을 넣지 않는다(현재 흐름 장표 1장 → 사례 ① 목업 시연).
6. **실제 SFA를 HTML로 충실 재현, 실데이터 자리는 가상 데이터**(ADR-012). 사용자가 준 기준 스크린샷(1888×952, 저장소 밖)과 배치·비율·색·모서리·그림자를 맞추고, 이름·숫자·일정·표·공지 제목은 `js/fixtures/` 가상 값으로 채운다. 로고·캐릭터는 실제 이미지(`img/logo.png`, `img/mascot.png`)를 쓴다(ADR-013·016, 저장소 외부 공개 시 `static/img/` 제외). 로고 이미지 밖의 HTML 글자로는 회사명·서비스명과 상품 브랜드를 쓰지 않는다(가상 상품명, CSS로 그린 중립 배너). 화면 안에 "시안" 표시를 두지 않고, 실제 동작이 없다는 점은 발표·시연 때 구두로 알린다(ADR-016). 재현도는 `scripts/ui_compare.py`로 확인한다(11절).
7. 시연용 강조(진입점 외곽선 깜빡임 등)는 선택 기능으로 두고 **기본 끔**.

### 0-3. 홈 디자인 대응표 (ADR-014)
새 화면의 요소는 아래 행 중 하나를 따른다. 크기(글자 18px·버튼 56px)와 강조색(`#0077b3`)은 0-2절이 우선이고, **모양(모서리·그림자·테두리 유무·색 계열·글자 간격)은 홈을 따른다.** 표에 없는 모양이 필요하면 먼저 행을 추가한다. 홈 값은 2026-11-03 Playwright 실측(1888×952), 패널 값은 S2(`css/panel.css`) 적용값.
| 새 요소 | 따르는 홈 요소 | 홈 실측 | 새 화면 적용 (S2 기준, `--pn-*`) |
|---|---|---|---|
| 글꼴·글자 간격 | 본문 전체 | Noto Sans KR, `letter-spacing -0.448px`(14px 기준) | 같은 글꼴, `-0.02em`(18px에서 -0.36px). 버튼·입력란도 상속 |
| 콘텐츠 카드(정보 묶음) | 업무 탭 카드·공지 카드(모양), 날짜 카드(그림자) | 흰 바탕, **테두리 없음**, 모서리 24px(`--sfa-card-radius`), `#f7f9fa` 바탕 위. 업무 탭·공지 카드는 그림자 없음, 날짜 카드만 `0 4px 20px rgba(64,96,128,.1)`(`--sfa-card-shadow`) | 테두리 없음·24px에 날짜 카드 그림자(`--sfa-card-shadow`)를 쓴다(패널 안 카드가 여러 장 이어져 구분이 필요해서). 안쪽 여백 20/24px, 마지막 요소 아래 여백 0 |

| 소제목 | "나의 활동량 / 고객" | 18px·700·`#292c33` | 18px·700, 위 여백 24px |
| 표·정의 목록 줄 | 업무 탭 표 | 줄 사이 1px 연한 선, 머리 글자 `#525866` | 줄 사이 1px `#e6ebf0`, 이름 칸 `#525866` |

| 입력란 | (홈에 없음 → 0-2절) | — | 56px·모서리 12px, 테두리 `#8a94a6`(흰 바탕 대비 3:1 이상, 예외로 유지) |
| 겹쳐 열리는 창 | 알림 팝업 | 모서리 12px, 1px `#e6ebf0`, 그림자 `rgba(163,177,204,.2)` | 오른쪽 패널(0-2절). 그림자는 `rgba(64,96,128)` 계열 |

**쓰지 말 것(S2에서 어긋났던 것).** 카드에 1px 테두리 + 그림자 겹치기, 왼쪽 굵은 색 띠, 같은 역할 버튼의 테두리 색·두께 섞기, 장식색(`#0099e6`)과 강조색(`#0077b3`) 겹쳐 칠하기, 색·모서리·그림자 값 직접 입력(토큰을 거친다).

| 왼쪽 열(31.3%) | 사용자 이름(가상)·부제, 오른쪽 위 작은 버튼 / **큰 파란 실적 카드**(두 칸 수치) / "나의 활동량 / 고객" 제목 / **남색 카드 2×3**(라벨+숫자) / **보라 카드 2개**(목록형 3줄) |
| 가운데 | **날짜 카드 슬라이더 4장**(좌우 화살표, 오늘 카드는 짙은 남색, 아이콘·"일정 없음" 문구) / **요약 알약 4개**(이번 달 생일·보험만기·납입만기·콜센터접촉 + 파란 원 숫자) / **업무 탭 카드**(가입설계 이력·청약진행현황·신계약보완·해피콜보완·계약문서열람 + 더보기, 표 머리 4열·2행) / 아래 왼쪽 **공지 탭 카드**(일반공지·시스템공지·CEO 메시지·영업자료실 + 목록) / 아래 오른쪽 **배너**(CSS 중립 그림) |
| 오른쪽 퀵메뉴 | 좁은 세로 열, 파란 원형 아이콘 + 2줄 글자, 은은한 카드, 세로 스크롤. 신규고객동의·기존고객동의·고객종합조회·가입설계·상세 보장분석·교육방송·UW 매뉴얼·챗봇·원격요청 등 |

**진입점 3개(새 기능).**
- 오른쪽 퀵메뉴의 원격요청과 챗봇 사이(5번째)에 기존 버튼과 **완전히 같은 모양**의 **"전산 오류 접수"** 한 칸. 1280×800 첫 화면에 보이는 위치. 상단 "제보"(보험사기 신고)는 건드리지 않음.
- 공지 탭 줄(일반공지, 시스템공지, CEO 메시지, 영업자료실) 끝에 5번째 탭 **"알려진 오류·내 신고"**. 실제 공지 카드는 126px 탭 3개 남짓만 들어가는 폭이라, 탭 높이·모서리·글자·색은 그대로 두고 공지 탭 폭을 글자 폭으로 줄여 5개를 한 줄에 둔다(탭 줄 오른쪽 넘김 버튼은 생략). 1600 미만에서는 배너를 공지 카드 아래로 내린다. 누르면 공지 카드 안에 S3 요약 줄이 보이고, 줄을 누르면 S3 패널이 열린다(5절, ADR-015).
- 상단 오른쪽 **기존 알림 아이콘에 숫자 배지**(0-2). 클릭 시 기존 알림 팝업 모양(0-1)으로 "내 신고 경과" 알림 목록. 항목을 누르면 S3 패널이 [내 신고] 탭으로 열리고 그 신고 카드로 이동한다(ADR-015).
- 데이터: 사용자·실적·활동량·일정·표·공지는 `js/fixtures/`(05번 형식 키). 사람 이름은 "(가상)" 또는 코드(FC-01).

## 4. S2 접수 패널 (ADR-017)
입력이 필요한 단계만 표시한다. B는6단계, A는5단계. known=off는 첫 단계 제외.
| 주소 단계 | 내용 | 비고 |
|---|---|---|
| 0 | 알려진 오류, 나도 겪었어요 / 다른 문제예요 | 동일 신고자 중복 방지 |
| 2 | 특정 고객에게만 생기는 문제인가요? + 자동 수집 정보 | 예이면 고객번호 별도 입력, AI 전송 제외 |
| 3 | 업무·증상 선택 | 필수 |
| 4 | 한 줄 설명 | 개인정보 주의·차단 분기 유지 |
| 5 | B 되묻기 최대3개 | A 생략, 실패 기본 질문 |
| 7 | 요약 확인, 선택적 내용 수정, 전달/저장 내용 펼침 | 완료 후 내 신고 바로가기 |
| 대리 | 관리자 누구의 신고인지 선택 | 상단 |

기존 step=1은2, step=6은7로 정규화. 내용 수정에 제목·설명·재현(B)·유형. 전달 내역은 B에서 AI에 전달한 내용, A에서 저장되는 내용으로 표시한다. 실제 전송 전 보안 통제는 백엔드에서 구현한다.
작성 중 X/Escape는 계속 작성/내용 지우고 닫기 확인. 탭 세션의 초안은 새로고침에서 복원하고 미작성 단계 직접 진입은 보정한다. 명시적 case·자체검사는 고정 시연을 위해 복원하지 않는다.
분기: 알려진 오류 종료, 사용법 안내/오류로 정정, 차단, AI 지연·실패, 고객·대리 접수 유지. llm=slow는 정지 시연이다.
디자인 대응: 자동 정보·요약·펼침은0-3 정보 카드, 편집은입력란·선택 버튼, 닫기 확인은안내 상자·기본/보조 버튼. 본문18px·행동56px와 --pn-* 토큰.

## 5. S3 알려진 오류·내 신고 (ADR-015, ADR-017)
- 공지 카드 요약4줄(내 신고 최신2+알려진 오류2). 상세는 오른쪽520px 패널, 1280 미만100%.
- 알려진 오류: 제목·상태·우회법·예정일/사유·건수와 직접 나도 겪었어요. 이미 신고했으면 알리고 중복 방지.
- 내 신고 기본: 제목·현재 단계 한 줄·막대·지금 할 일. 우회법과 승인 안내의 중복 제거. 번호·전체 단계·안내 전문은 자세히 보기. 승인본만 표시.
- 진행중/끝난 신고 분리, 끝난 묶음 기본 접기. item 대상은 묶음과 상세를 펼치고 이동.
- 관리자 내가 대신 보낸 신고 묶음. 본인 신고와 중복하지 않음.
- 받은 알림은 접힌 이력. 항목 선택 시 읽음, 배지는 미확인 건수.
- 빈 화면에는 접수 방법 안내. 완료의 내 신고에서 보기로 해당 새 신고 이동.
- ApiClient가 fixtures 초기값과 세션 가상 변경을 합침(05번). 실제 저장·알림·AI 연결은 BACKEND.

## 6. S4 결함 대장
- 목록: 유형, ID, 신·구, 영향 지점 수, 신고 수, 등급, 상태, 부서. 기본 정렬 영향 지점 수 × 업무 중요도. 필터.
- 상세: 연결된 신고 목록, 상태 이력, 우회법·예정일.
- 신고 연결(미연결 신고 목록에서 선택).
- 상태 변경 대화상자: 다음 상태 선택, 예정일/사유 입력 → **"묶인 신고자 N명에게 알림" 미리보기** → 확정.
- 안내문: AI 초안 생성 → 수정 → 담당자 승인(S).

## 11. 화면 검증 절차
사람이 매번 브라우저로 확인하지 않아도 되도록, 화면 PR마다 자동 검사를 돌리고 캡처를 눈으로 본다(11번 문서 1절 "화면 자동 검사").

**상태 주소(해시).** 화면 상태는 주소 `#` 뒤에 적어 그대로 재현한다. 클릭하면 주소도 바뀐다.
| 키 | 값 | 뜻 |
|---|---|---|
| `role` | `FC` `MANAGER` `SALES` `IT` | 보는 사람 역할(화면 안 전환 버튼 없음, ADR-016) |
| `user` | `U-001` 등 | 사용자(없으면 그 역할의 첫 사용자) |
| `popup` | `alarm` | 알림 팝업 열림 |
| `notice` | `next` | "다음 단계에서 구현됩니다" 안내 상자 열림 |
| `demo` | `1` | 진입점 3개 강조 외곽선(시연용, 기본 끔) |
| `board` | `known` | 공지 카드에서 "알려진 오류·내 신고" 탭 선택(S3 요약 줄). 없으면 일반공지. 다른 공지 탭은 `system` `ceo` `sales` |
| `panel` | `intake` `known` | 오른쪽 패널: S2 접수(`js/intake-panel.js` 머리 주석의 `step` 등 키) / S3 알려진 오류·내 신고. 값이 하나라 둘은 동시에 열리지 않음 |
| `tab` | `known` `mine` | S3 패널 전환 탭(없으면 `known`) |
| `item` | `D-2026-004`, `R-011` 등 | S3 패널에서 이동할 카드(알려진 오류는 결함 ID, 내 신고는 신고 ID). 알림 항목에서 열면 붙음 |
| `step` | `0`~`7` `metoo` `usage` `done` | S2 단계(4절 번호; 1→2, 6→7 호환)와 끝 화면(알려진 오류로 종료·사용법 안내로 종료·접수 끝). 끈 단계 번호면 다음 단계로 |
| `mode` | `A` `B` | A: AI 끔(5단계 없음, 6단계는 저장용 마스킹 결과만) / B: AI 켬(기본) |
| `known` | `off` | S2 0단계(알려진 오류) 끔(S5 실험 재사용) |
| `llm` | `ok` `slow` `fail` | AI 응답: 정상(기본) / 늦음(5단계 로딩에서 멈춤) / 실패(규칙 되묻기) |
| `case` | `defect` `customer` `usage` `blocked` | 예시 사례: 빈 칸을 이 사례의 가상 입력으로 채우고 고정 응답을 고른다. 열린 채로 값이 바뀌면 다시 채운다 |
| `alert` | `blocked` | 4단계 입력 차단 경고 |

쿼리 `?compare=1` 은 `scripts/ui_compare.py` 캡처용 표시(`<html class="compare">`)만 붙인다. 화면 밖 시안 띠가 없어져(ADR-016) 지금은 숨길 요소가 없다.
예) `index.html#role=FC&popup=alarm`, `index.html#role=FC&board=known&panel=known&tab=mine&item=R-011`

**요소 표시.** 검사 대상은 HTML 속성으로 구분한다.
- `data-a11y="new"`: 새 요소(안내 상자, 패널, 배지·팝업 내용). 글자 18px 이상, 클릭 요소 높이 56px 이상.
- `data-a11y="sfa"`: 기존 SFA 모양(진입점 포함). 0-1 토큰과 일치(퀵메뉴 96px·모서리 16px·글자 14px, 공지 탭 높이 44px·모서리 12px·글자 14px·폭 60px 이상, 5개가 탭 줄 안 한 줄).
- `data-clip-ok`: 원래 화면처럼 일부러 잘라 보이는 영역(날짜 카드 슬라이더). 글자 잘림 검사 제외.
- `data-a11y="replica"`: 실제 SFA를 재현한 기존 요소와 그 안의 가상 데이터(ADR-012). 원본 모양 유지가 우선이므로 글자 크기·대비 검사 제외(진입점은 `sfa`로 따로 검사).
- `data-a11y="badge"`: 알림 배지. 0-2 값(배경 `#d93025`, 흰 글자, 최소 18px)과 대비만 검사(기존 아이콘 위 작은 숫자라 18px 글자 기준 제외).

**자체 검사.** `index.html?selftest=1#<상태>` 로 열면 `js/dev/selftest.js` 가 실행되어 `<pre id="selftest-result">` 에 `{ok, checks:[{name, pass, detail}]}` 를 남긴다. 항목: 새 요소 크기, SFA 토큰 일치, 대비(4.5:1, 큰 글자 3:1, replica 제외), 가로 넘침·글자 잘림 0건, 보이는 글자·탭 제목에 "시안" 없음(ADR-016), 패널 맨 아래가 행동 줄(S2)·본문(S3). 평소 열 때는 실행되지 않는다.

**실행.** 작업 트리 루트에서
```
python scripts/ui_check.py
```
- Chrome(없으면 Edge)을 headless로 실행해 상태 × 폭(1280×800, 1888×952, 1920×1080) 조합마다 캡처(`target/ui-check/<상태>_<폭>.png`, Git 제외)와 자체 검사를 한다.
- 정적 검사: `static/` 아래 외부 주소(`http://`·`https://`·`//cdn`)·`fetch(`·`XMLHttpRequest` 0건, 주민·휴대폰·카드·긴 숫자 형식 0건, 성씨로 시작하는 한글 3글자 낱말은 UI 낱말이거나 바로 뒤에 "(가상)"이 있어야 함, 주석을 뺀 코드에 시안 표시 문구("화면 시안"·"시안 조절"·"시안:")와 시안 띠·줄 클래스 0건(ADR-016).
- 조합별 PASS/FAIL 표를 출력하고 하나라도 실패하면 종료 코드 1.
- 자동 검사가 통과해도 캡처를 열어 0절 원칙(기존 화면처럼 보이는가, 새 요소가 기존 모양과 같은가, 문구가 쉬운가)을 눈으로 확인한다.

**디자인 일관성 검증(ADR-014).** 자동 검사는 접근성 하한만 본다. 홈과 같은 시각 언어인지는 아래 두 단계로 확인한다.
1. **착수 전 – 대응표.** 새 화면에 쓸 요소를 나열하고 각각 0-3절의 어느 행을 따르는지 PR 본문 "디자인 대응표"에 적는다. 표에 없는 모양은 0-3절에 행부터 추가한다.
2. **완료 후 – 실측 비교.** 자동 검사 통과 뒤 디자인 일관성 리뷰어(`.claude/agents/design-consistency-reviewer.md`)를 서브에이전트로 돌린다. 리뷰어는 읽기 전용으로, 로컬 서버(`python -m http.server`, Playwright는 `file://`을 막음)로 연 화면에서 홈과 새 화면의 계산 스타일(글꼴·글자 간격·모서리·그림자·테두리·색)을 실측해 0-3절과 비교하고, ① 어긋남(실측값·제안 CSS) ② 시각 버그 ③ 잘 맞는 점(건드리지 말 것)을 보고한다. 지적 사항을 같은 PR에서 고치고 `ui_check.py`를 다시 돌린다. 심각하지 않은 동작 버그는 별도 `fix/` 브랜치로 뺀다.
- S4~S6(SFA 밖)은 홈 대신 S2 패널을 기준으로 비교한다(ADR-014 결정 5).
- 리뷰어 캡처는 `target/` 아래에만 저장하고, 끝나면 로컬 서버를 끄고 `.playwright-mcp/` 기록을 지운다.

**실제 SFA 재현도 비교(ADR-012).** 기준 스크린샷은 저장소 밖에 두고, 원본을 직접 열지 않는다.
```
python scripts/ref_blur.py "<스크린샷>" [--blur 6] [--crop x,y,w,h] [--zoom 2] [--out 경로]
python scripts/ui_compare.py "<스크린샷>" [--blur 6] [--offset-y N]
```
- `ref_blur.py`: 흐림 사본을 만든다(기본 `target/ref-blur/`). blur 6 미만은 거부. 확대는 흐림 **뒤**에 해서 글자가 읽히지 않는다. Claude는 이 사본만 본다.
- `ui_compare.py`: `index.html?compare=1` 을 원본 크기로 headless Chrome 캡처하고, 두 이미지에 같은 흐림을 적용해 전체 유사도(%)와 8×6 격자별 유사도를 표로 출력한다. `target/ui-compare/` 에 흐림 원본·흐림 재현을 **반반 겹친 PNG**(`overlay.png`)와 **나란히 놓은 PNG**(`side.png`)를 저장한다. 원본을 흐림 없이 출력·저장하지 않는다. `--offset-y` 는 스크린샷 맨 위가 잘린 만큼 우리 캡처를 위로 당긴다.
- 숫자보다 겹친 이미지에서 상자 위치·크기·색이 맞는지를 우선 본다. 가상 데이터 글자 차이는 허용.

### ADR-017 디자인 리뷰 보완
S2의 독립 펼침 영역은 정보 카드(24px·카드 그림자), S3 카드 내부의 펼침은 보조 버튼(12px·연한 테두리·그림자 없음)을 따른다. 같은 카드 안에 그림자를 중첩하지 않는다. 최종 수정 제목은 내 신고에서도 사용하고, 제목과 다른 설명은 상세에서 확인한다. 해결된 신고는 이전 우회법과 지난 수정 예정일 대신 업무 재개 안내를 표시한다.
